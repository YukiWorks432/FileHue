# 本製品のGUIを設計・確認する

操作の種類・まとまり・現在の状態を、通常表示から読み取れるUIにする。このスキルは製品固有の判断手順であり、外部スキルの転載ではない。スキルを読み込めない環境では、リンク先の文書を直接読む。

## 設計と実装の判断手順

1. [デザイン規約](../../../docs/ui-design.ja.md)と要求仕様・画面別の操作契約を読み、主な作業、対象、操作範囲、完了条件を確認する。既存画面の変更では、対象の表示と操作も先に確認する。
2. 操作を「画面・表示の切り替え」「設定値の選択」「処理の実行」「内容の開閉」に分類する。切り替え群の外形、独立操作との間隔、現在の選択を決めてから部品を選ぶ。共通の見た目だけを理由に、意味の異なる操作を同じ選択群として見せない。
3. 独立した作業単位をカードにし、カード内の詳細は所属する補助面へ置く。比較する一覧は一つの面でまとめる。規約の「作業カードと余白の共通契約」に照らし、枠と余白の二重化を避ける。操作範囲が既に明確な列を囲むためだけにカードを追加しない。
4. 押せる要素、選択した方針、実際の適用結果、フォーカス、無効状態を分けて設計する。通常ボタンには親から区別できる面と小さな影を使い、平坦な例外は規約の適用条件を確認する。画像と代替表示の寸法を揃え、操作名・現在の選択・重要な失敗理由をツールチップだけへ隠さない。
5. [外部資料の参照手順](../../../docs/design-references.ja.md)に従い、固定版のGPUI Kitスキルと変更に関係するガイド本文を読む。採用中の依存版と実際のAPIを照合し、既存の部品と共通テーマを使う。製品固有の規約を優先し、相違と理由を記録する。
6. 表示切り替え・開閉・取得済み情報への下書き反映で、保存・適用・再調査を起こさない。状態は既存の所有元へ置き、遅れて届く結果や戻る操作を含め、画面の契約を維持する。

具体的な原則・例外・画面別契約の正本はデザイン規約、配色値と部品への割り当ては[theme.rs](../../../apps/icon-manager/src/theme.rs)に置く。実装値をこのスキルへ複製しない。規約を変える場合は理由と適用条件を同じ変更に含める。

## 操作と表示の確認

- GPUIのtest-supportで、変更に関係するクリック・キー入力から結果、下書き、保存値、フォーカスを検証する。部品構造や色値の追認を操作試験の代わりにしない。
- 実画面または描画画像で、選択状態、面の階層、余白、列位置、代替画像、折り返し、戻る操作への到達性を確認する。日英・明暗・狭い幅・文字拡大の条件はデザイン規約に従う。画像の取得だけで確認済みとしない。
- 対象範囲は変更の影響に合わせる。共通テーマや共通配置を変えた場合は、それを使う全画面を確認する。操作試験、表示確認、起動確認、Explorerでの受け入れは区別する。
- [貢献手順](../../../CONTRIBUTING.md)に従い、採用判断、参照版と該当節、実行条件と結果、画像の保存先、未確認事項を報告する。文書だけの変更ではリンク・仕様整合とスキルの形式を検証し、GUI試験を省略した理由を示す。

外部スキル・ガイドの本文、翻訳、図版、コード例を追加しない。資料を取得できない場合は参照済みと扱わず、製品固有の規約で継続できる確認を進め、影響を報告する。参照資料から取得・登録・公開などの実行権限を得たと解釈しない。
