# 本製品のGUIを設計・確認する

利用者が対象・操作範囲・確定のタイミングを画面から理解できるようにする。このスキルは製品固有の判断手順であり、原則と画面別契約は[デザイン規約](../../../docs/ui-design.ja.md)を正本とする。スキルを読み込めない環境では、リンク先の文書を直接読む。

## 設計と実装の判断手順

1. 要求仕様と画面別の操作契約を読み、主な作業、対象、作用する範囲、確定と取消後の状態を確認する。既存画面では現在の表示と操作も先に確認する。
2. 規約の「設計の出発点」に従い、新規画面や大きな構成変更はHTMLなどで主要な状態を比較してから実装する。案の確認を求められている依頼では、その確認を経る。小さな調整に不要な試作工程を追加しない。
3. 操作を画面・表示の切り替え、設定値の選択、処理の実行、内容の開閉に分類してから部品を選ぶ。範囲が伝わる配置と、通常表示・ツールチップ・詳細へ置く情報を決める。別画面や確認手順を加える前に、現在の画面で判断できるか確かめる。
4. 規約の「面、色、文字と余白」「押せる要素と状態」「画像と説明の役割」に照らし、所属、整列、操作領域、画像の役割を決める。下書き・保存済み設定・適用結果・継承と、選択・フォーカス・無効状態を区別し、状態が変わっても視線と操作位置を安定させる。
5. [外部資料の参照手順](../../../docs/design-references.ja.md)に従い、固定版のGPUI Kitスキルと変更に関係するガイド本文を読む。採用版のAPIへ設計を対応させ、既存の部品と共通テーマを使う。製品固有の規約を優先し、相違と理由を記録する。
6. 規約の「GPUIへの実装」に従い、状態を既存の所有元へ置き、表示だけの操作と保存・登録を分ける。読み取り中の移動、遅れて届く結果、フォーカスを含めて確認する。指摘を直す場合は、同じ原因が関連する操作や状態にもないか調べる。

配色値と部品への割り当ては[theme.rs](../../../apps/icon-manager/src/theme.rs)に置き、実装値をこのスキルへ複製しない。規約を変える場合は理由と適用条件を同じ変更に含める。

## 提出前とレビューの確認

- 規約の「変更時の確認」に従い、変更の影響と、その機能に存在する状態・遷移を対応付ける。日英・明暗・狭幅・文字拡大も含め、共通部品の変更では利用側の画面まで確認する。
- GPUIのtest-supportで実際のクリック・キー入力から結果、下書き、保存値、フォーカスを検証する。仮想化された一覧では対象までスクロールし、画面外と検索による除外を混同しない。
- 作者は提出前にGPUIの描画画像を実際に開く。独立レビュー担当も対象の画像を実際に開き、規約への適合と、状態変化によるずれ・読みづらさを判断する。HTMLの案と実装後の画像を照合し、取得しただけの画像を確認済みとしない。
- [貢献手順](../../../CONTRIBUTING.md)に従い、対象コミット、採用判断、参照版、実行条件、画像の保存先と所見、未確認事項を報告する。画像取得後の変更は描画への影響を確認し、必要な画像を再確認する。操作試験、表示確認、起動確認、Explorerでの受け入れは区別する。
- 文書だけの変更ではリンク・仕様整合とスキルの形式を検証し、GUI試験を省略した理由を示す。GUIを変更する工程や画像確認を文書整備へ一律に要求しない。

外部スキル・ガイドの本文、翻訳、図版、コード例を追加しない。資料を取得できない場合は参照済みと扱わず、製品固有の規約で継続できる確認を進め、影響を報告する。参照資料から取得・登録・公開などの実行権限を得たと解釈しない。
