# アイコン適用対象の選択

パックの元の定義を保持したまま、カテゴリ・拡張子・固有名・パターンごとに適用対象を選択できます。GUIと補助CLIは同じ設定、管理ロック、解決処理を使います。取得や選択の編集だけでExplorerの表示は変えません。

## 判定規則

`.lnk` と `.exe` はWindowsが管理する保護対象とし、常にテーマ適用から除外します。大文字・小文字、固有名、親フォルダー条件、複合拡張子、パターン、個別指定より保護を優先します。リンク先は本アプリで解析・追跡しません。それ以外の初期値はすべて有効とし、従来の選択を保持します。固有名の個別指定、パターンの個別指定、拡張子の指定、初期値の順に適用可否を決めます。同じ種類では直接の親フォルダー条件を優先し、複合拡張子は長いものを優先します。パターン間の優先順位は元の定義と同じ辞書順とします。比較は大文字・小文字を区別しません。

対象を無効にした場合はWindowsの元の表示へ戻します。名前の無効化を、拡張子のパック画像へ置き換えてはなりません。テーマ内の画像を探す優先順位は従来どおり維持し、選択設定だけでテーマ未定義の画像は作りません。

| 選択 | 結果 |
| --- | --- |
| extension:jsonを無効 | data.jsonと、個別指定のないpackage.jsonは元の表示 |
| 上記にfile:package.jsonの有効を追加 | package.jsonだけテーマの画像 |
| extension:mdを有効、file:readme.mdを無効 | notes.mdはテーマ、README.mdは元の表示 |
| file:readme.mdの個別指定を解除 | 拡張子mdの設定に従う |

拡張子のない名前と、取り込み済みの親フォルダー条件・パターンも対象とします。設定できる識別子は対象一覧が返すものに限ます。

言語のパターンによる選択は、画像の名前解決と同じ範囲へ作用します。名前だけのglobはファイル名を照合し、`config/*.wfi-test` のような条件は直近の親と名前を照合します。その無効化はconfig直下の該当ファイルだけを通常表示へ戻し、別の親やconfigの孫には作用しません。`**/rebase-merge/done` の先頭の `**/` も許可するが、祖先の探索は追加しません。複数の親階層を必要とする `**/.github/hooks/*.json` 等は対応範囲外です。保存、再読み込み、パック間の対象コピーでも同じ判定を使います。

大小文字だけが異なる同じパターンは一つの対象へ統合します。異なる画像への矛盾する指定は取り込み・再読み込み時に拒否し、個別指定の識別子は従来どおり小文字で保持します。正常な旧記録の別表記と保存済みの個別指定は同じ対象に作用します。明確に異なるパターン同士の重なりは許可し、既存のキー順で判定します。

## 用途別カテゴリの判定

分類は全パックで共通とし、同じ種類・名前の対象には同じカテゴリを返します。Windowsの関連付けやパック固有の画像名から分類を推測しません。アプリには分類表とVS Code由来の言語定義を組み込んでいます。言語定義の版・出典・利用条件はソースで管理し、実行時の通信は行いません。

| カテゴリ識別子 | 用途と境界の例 |
| --- | --- |
| `language` | Rust、Python、SQL、Lua、Dartなどのソースやスクリプト |
| `web` | JavaScript、TypeScript、HTML、CSS、Web向けのテンプレートやフォント |
| `data` | 汎用のJSON・TOML・YAML、データベース、ログ、`tsconfig.json`などの設定 |
| `documents` | 説明文、文書、表計算、プレゼンテーション、拡張子のない`LICENSE` |
| `build` | `package.json`、`Cargo.toml`、`requirements.txt`、ロックファイル、ビルド定義、コンテナー構築・構成 |
| `tools` | Gitの管理用ファイル、差分、開発支援ツールへの指示書、除外設定 |
| `media` | 画像・音声・動画と、その編集用のプロジェクト |
| `archives` | ZIP、7z、tar.gzなどの圧縮・アーカイブやディスクイメージ |
| `other` | 対応表にないもの、複数の用途が競合して確定できないもの |

カテゴリは対象ごとに一つとします。固有名は、分類表の完全一致、同梱言語定義の完全一致、同梱言語定義の名前パターン、拡張子の順で調べます。完全一致では`package.json`をビルド関連として扱い、汎用のJSONと区別します。拡張子は長い複合拡張子から調べ、同じ拡張子ではアプリの分類表を言語定義より優先します。異なる用途の言語情報が競合する場合は未分類にします。

大文字・小文字は区別しません。固有名の完全一致と拡張子の照合では直接の親フォルダー条件を除いた名前を使い、同梱の名前パターンが親フォルダーを含む場合はその条件も照合します。拡張子の対象を固有名として解釈しないため、`file:package.json`は`build`、`extension:package.json`は`data`になります。パターンの対象は、同梱言語定義のパターンと完全一致する場合、または`*.sql`のように拡張子部分が固定された場合にだけ分類します。`*`や`*.{rs,json}`など、広い範囲や異なる用途を含み得る指定は未分類に残します。`.git`という接頭辞だけで開発ツールに分類せず、既知の固有名を照合します。

カテゴリ自体は設定に保存しません。分類表の更新後も対象識別子と個別の適用可否を維持し、カテゴリ全体の操作は更新後の所属対象へ働きます。`.exe`と`.lnk`の保護は分類にかかわらず優先します。

## GUI

パックの「適用対象を選ぶ」から編集画面を開きます。左にカテゴリ、中央に検索と対象一覧を配置します。表示の確認とテーマ間コピーは、上部の専用ボタンから別の作業面へ切り替えます。保存・適用・取り消しは画面下部に固定し、各列をスクロールしても操作できます。カテゴリは開発言語、Web、データ・設定、文書、ビルド・依存管理、バージョン管理・開発ツール、画像・音声・動画、圧縮・アーカイブ、その他・未分類です。アプリの共通分類であり、曖昧なものは未分類へ置きます。カテゴリは一括編集の入口とし、独立した設定の優先順位は持たせません。

カテゴリ名と対象に含めた件数は別の行に表示します。カテゴリを選ぶと一覧上部に「カテゴリ全体を対象に含める」と対象数／総数を表示します。件数は保護反映前の選択範囲であり、実際にパックを使うかどうかは各行の表示予定で確認します。一部のみ適用している場合も件数から判断できます。このチェックは検索条件とは独立して、そのカテゴリ内の固有名の例外も含めて変更します。検索結果の一括操作は現在のカテゴリ・検索・状態絞り込みに一致する対象だけを変更し、同じ操作帯に対象件数を表示します。「複数選択」を有効にしたときだけ行選択のチェック欄を表示し、その間は一括操作の範囲を選択行へ切り替えます。

対象一覧は100件ごとに表示し、前後へ移動できます。一括操作は表示中の100件だけでなく、明記した検索結果全件に対して働きます。対象に含む、対象外、個別設定あり、変更あり、保護中で絞り込めます。各対象には種類、画像、個別指定がある場合はその状態を表示します。「対象」のチェックはパックの使用範囲を示し、保存後の表示予定を別に示します。既存アイコンの保護中、パックを使用、対象外、対応画像なし、調査中、調査失敗を区別し、保護中でも一覧から除外しません。パターンは具体的なファイル名で結果を確認します。ファイル名入力では保存済みと下書きの対象選択・保護方針を合わせた結果と理由を比較でき、画像を取得できない場合に元の表示の画像を推測して見せません。

検索は選択中のカテゴリと状態の範囲で行います。たとえばTypeScriptの `.mts` は「Web」に分類され、「開発言語」だけの検索では表示されません。別の範囲に一致する対象がある場合は「全対象から検索」で入力を保ったままカテゴリと状態の絞り込みを解除できます。パック全体にも一致する対象がない場合は、対応定義に見つからないことを表示します。保護が原因で対象が一覧から消えることはありません。

行の「保護」から補助面を展開し、「元のアイコン」「パックのアイコンを許可」「基本設定に従う」の画像付き三択で拡張子の保護を変更できます。この設定は全パック共通であり、対象選択の下書きとは分離します。未保存の保護設定は下部の専用操作で保存または破棄します。適用中のパックがあれば、保護の保存でそのパックを再適用します。保護の下書きがある間は対象選択の保存・適用を無効にし、設定を取り違えた確定を防ぎます。対象一覧から戻ると未保存の保護変更は破棄し、対象選択の下書きは従来どおり保持します。ソフト単位の保護画面へ移動した場合は共通の保護下書きを引き継ぎ、戻ると保存済みの保護へ戻します。

同じWindowsの関連付けクラスを使う拡張子も、保護設定は独立して判定します。たとえば`.mts`をパックへ変更しても、`.m2ts`の保護は維持します。表示予定と「基本設定に従う」の画像は、その種類自身の方針へ追随します。選択や三択の変更で再調査せず、保存するまではWindowsへ適用しません。

編集はテーマごとの下書きに保持し、他のテーマへ移動しても失いません。上部の「戻る」、Alt＋←、マウスの戻るボタンは同じ移動を行います。比較・コピー・カテゴリの補助画面からは対象一覧へ、対象一覧からは元のパック画面へ戻り、下書きを保持します。直近32回の操作を取り消せます。「保存済みに戻す」は下書きを破棄します。「継承へ」は対象の個別指定を取り除きます。別テーマの保存済み選択をコピーするときは、対応する識別子だけを引き継ぎ、対象外の件数を事前表示します。コピー元にない対象についてはコピー先の選択を保持します。コピーも取り消せます。

未適用テーマは「選択を保存」で保存します。「この設定で適用」は保存後にテーマを適用します。適用中のテーマは「変更を適用」で反映します。全対象を無効にすると適用を解除します。失敗したときは下書きを残し、エラーと復旧状態を表示します。Explorerは自動終了しません。

登録調査が完了すると、見本の生成を待たずに対象と保護設定を表示します。見本の読み込み中は待機表示とし、方針を編集できます。見本を取得できなかった場合も登録情報による保護は維持します。別の調査や画面へ移動した後に届いた見本は、現在の画像を置き換えません。

### 一覧と補助画面の配置

カテゴリ欄はGPUI Kitの`List`と`ListItem`による単一選択の一覧とします。「すべてのカテゴリ」も同じ二段の行で左寄せにし、上段に名前、下段に「適用数／総数」を示します。一覧全体の枠と行の区切りを残し、確定したカテゴリは背景、キーボードで移動中の行はフォーカス枠で区別します。上下キーは移動だけを行い、Enterまたはクリックで絞り込みを確定します。カテゴリの切り替えでは適用可否を保存しません。狭い画面ではカテゴリの入口から一覧へフォーカスを移し、確定後は検索欄へ戻します。Escでは絞り込みを変えずにカテゴリ選択を閉じます。

通常の作業は「カテゴリまたは名前で探す」「適用のチェックを変える」「保存する」の順に進めます。カテゴリ名の下に適用件数を分けて示し、長い分類名も途中で省略しません。カテゴリは絞り込みの入口であり、一括指定は選んだカテゴリの一覧上部で行います。

一覧では、画像、対象名、種類と個別指定の有無、適用チェック、個別指定の解除を同じ列位置で読めるようにします。適用チェックは下書きへの変更であり、保存するまで反映しません。行選択は通常は表示せず、「複数選択」で明示的に開始します。この間だけ先頭に行選択欄を表示し、一括操作は選択行へ作用します。非表示の行を含む選択件数を示し、選択解除と終了を提供します。終了しても選択と下書きは保持し、再開できます。

検索・状態の絞り込み・一括操作は一覧の上、変更件数・取り消し・保存・適用は下に固定します。スクロールするのは対象一覧です。保存・適用の実処理中は下部の保存ボタンの手前にスピナーと「保存中…」または「適用中…」を表示します。処理中は編集と再送信を抑止し、成功・失敗後はスピナーを消して結果へ切り替えます。表示を見せるための待ち時間は加えません。検索結果全件または選択行の件数を、一括操作と同じまとまりに一度だけ表示します。結果が空なら検索と絞り込みをまとめて解除できます。

表示確認と設定コピーは常時表示する右側の列へ詰め込まず、上部の「表示を確認…」「設定をコピー…」から全幅の作業面へ切り替えます。戻るボタンまたはEscで対象一覧へ戻り、下書き・検索・選択を保持します。コピー元のパック名と対象外件数はボタンから分離し、長い名前も折り返して確認できます。「この設定をコピー」を押すと下書きへコピーして一覧へ戻ります。

名前パターンだけに一致するファイルも、実効関連付けを非同期で確認してから保存済み・予定の結果を示します。編集中のパックの登録計画を基準とし、別パックの適用情報を流用しません。パックの登録対象でも既存の関連付けでもない拡張子は、Shellと同じく `Unknown` の保護に従います。確認中または取得失敗時に、パックのアイコンを使用できると断定しません。

幅が基準文字の64倍未満ならカテゴリも専用の入口から切り替え、一覧の幅を確保します。カテゴリ選択後は一覧へ戻ります。言語・明暗の操作はパック一覧と共通にします。長い対象名は行内で省略し、対象名のツールチップと適用チェックのアクセシブル名で全体を確認できます。パック名も一行に省略し、ツールチップで全名を確認できます。寸法・余白・文字はKitの相対尺度、色は意味別トークンを使います。

## CLI

識別子と現在値は次で確認します。対象識別子、カテゴリ、JSONキーは表示言語によって変わりません。

```powershell
.\file-icons.exe targets list "<pack-id>" --json
.\file-icons.exe targets edit "<pack-id>" category:data off --dry-run
.\file-icons.exe targets edit "<pack-id>" category:data off
.\file-icons.exe targets edit "<pack-id>" file:package.json on
.\file-icons.exe targets edit "<pack-id>" file:package.json inherit
.\file-icons.exe targets edit "<pack-id>" query:json off
.\file-icons.exe targets copy "<source-pack-id>" "<destination-pack-id>" --dry-run
```

editの範囲はall、category:<分類識別子>、query:<名前の部分文字列>、一覧が返す対象識別子です。値はon、off、inheritです。GUI同様に、適用中のテーマでは反映、未適用テーマでは保存だけを行います。新しいパックの適用はapplyで明示します。

複数の任意対象はUTF-8 JSONを一回の保存で反映できます。上限は1MiBです。trueは有効、falseは無効、nullは継承へ戻します。未知の対象や不正な値を一つでも含む場合は全体を拒否します。

```json
{"extension:json": false, "file:package.json": true, "file:readme.md": null}
```

```powershell
.\file-icons.exe targets set "<pack-id>" changes.json --dry-run --json
.\file-icons.exe targets set "<pack-id>" changes.json --json
.\file-icons.exe resolve "<pack-id>" package.json --json
```

## 分類表の保守と未分類の確認

分類表を変更するときは、用途が分かる固有名を優先し、通常の拡張子の分類を必要以上に変えません。言語情報が共通の用途を持つ場合は`language_ids`へ対応を追加し、VS Codeの組み込み定義にない拡張子やアプリ独自の例外は`extensions`・`filenames`へ追加します。既存のカテゴリ識別子は維持します。新しいカテゴリを加える場合は、カテゴリ名の日英表示と上の用途表も更新します。

言語定義を更新したときは、未確認の言語識別子を検出する共通処理の試験を通します。さらに取り込み済みパックごとに未分類の件数と名前を確認します。次はリポジトリ直下で実行する例で、設定や登録を変更しません。結果は対象規則の数であり、実際のファイル数ではありません。

```powershell
$packId = "<pack-id>"
$result = & .\target\debug\file-icons.exe targets list $packId --json
if ($LASTEXITCODE -ne 0) { throw "適用対象の取得に失敗しました" }
$rows = ($result | ConvertFrom-Json).data.targets
$unclassified = @($rows | Where-Object { $_.target.category -eq 'other' })
"未分類: {0} / 全対象: {1}" -f $unclassified.Count, @($rows).Count
$unclassified | ForEach-Object { $_.target.id } | Sort-Object
```

vscode-icons、Material Icon Theme、Catppuccin Iconsの取り込み済みテーマをそれぞれ確認し、共通する未分類対象から改善します。パックに含まれない対象を分類のために新設しません。広いパターンや意味が不明な独自拡張子は、件数を減らすためだけに別カテゴリへ入れません。

## 保存とShell

管理用設定とShell用設定は形式4を使用し、非対応形式の読み込みと通常保存を拒否します。管理用は全テーマの選択、Shell用は適用中の選択の写しを保持します。未適用テーマだけの編集でShell用ファイルを書き換えません。二番目の保存に失敗した場合は管理用ファイルを以前の内容へ戻します。戻す処理も失敗した場合はエラーを返し、独立した復元記録を保持します。適用中の選択変更は同梱DLLを配置し直して再適用し、切り替え失敗時は旧選択と旧DLLへ復帰します。Explorerが旧DLLを読み込み済みの場合は再起動が必要になります。

素材と出典は変更しません。テーマの再取得・同一識別子での再取り込みでも選択は保持し、異なるテーマの追加で勝手に有効化しません。パック削除ではそのパックの選択も削除します。同一テーマの再取り込みで定義から消えた対象の指定は取り除きます。設定APIへ未知の対象を追加する要求は拒否します。

Windowsでは複数の拡張子が同じ関連付けクラスを共有することがあります。登録単位と選択単位を分け、Shellで実際のファイル名に対して適用可否を判定します。無効な対象は登録前のハンドラーまたは画像へ委譲します。既定アプリは変更しません。保護対象の関連付けクラスを除き、全対象が無効になった場合以外は元のパックの登録範囲を保持します。

## 受け入れ確認

拡張子と固有名の例外、無効化後の通常表示、複合拡張子、拡張子なし、親条件、パターン、コピー、保存往復、未知対象の一括拒否を試験します。GUIではGPUIのtest-supportで検索、一括変更、取り消し、保存、日英切替、保存失敗後の再試行を実操作します。CLIは実プロセスのJSONと終了コード、dry-run時のファイル保持を検証します。登録とDLLの試験は専用レジストリへ隔離し、通常の利用者設定を書き換えません。

## Windowsが管理するアイコンの保護

ショートカットと実行ファイルは、リンク先・個別指定・実行ファイル内の資源によって固有のアイコンを持つため、テーマの共通画像で置き換えません。原テーマの規則・素材は削除せず、実際の解決と登録計画で除外します。保護対象と同じ関連付けクラスを共有する別拡張子からも、そのクラスの登録を書き換えません。Shellの実行時も保護を判定し、既存登録を通って呼ばれた場合は元の表示に委譲します。ファイル内容、起動設定、ショートカットの矢印は変更しません。

GUIは保護対象を一覧に残し、適用チェックを無効化して理由を表示します。カテゴリ・検索結果・選択行の一括有効化でも有効にしません。CLIのtargets listは各行にprotectedを付けます。resolveのreasonはprotected_file_type、iconはnull、selection_enabledはfalseを返します。対象識別子を明示した有効化とJSON差分での有効化は前提条件エラーとし、要求全体を保存しません。一括操作は保護対象を除いて実行します。コピーも保護対象を有効化しません。

旧設定の保護対象への個別指定は読み込み時に取り除き、設定全体を読めなくしません。既存のレジストリ登録は起動や設定読み込みだけで変更しません。次の明示的な適用・適用中の選択変更で、既存の復元記録を使って旧登録を戻した後、保護対象を除いて再登録します。他者による変更があれば上書きせず競合を報告します。保護対象だけのテーマは有効対象なしとして既存登録を復元します。Explorerが旧DLLや画像を保持している場合は再起動が必要になります。

試験は保護対象への完全一致・パターン・大文字・複合拡張子、旧選択の読み込み、CLIの失敗時の無変更、GPUI test-supportのクリックと一括操作、隔離レジストリの旧登録復元、実DLLとShellから返る小・大アイコンの画素保持を確認します。通常プロファイルへの登録と実Explorerの画面受け入れは別に行います。

## 既存アイコンの保護設定

画面上部の「アイコンの保護」から、全パックに共通の「既定では既存アイコンを保護する」を設定します。既定で有効とします。確認するパックを選ぶと、元の画像を保護する種類とパック画像を許可する種類を一つの一覧で確認・変更できます。初期表示は「すべて」で、「保護」「パック許可」「要確認」「適用中の除外」へ絞り込めます。絞り込み中の変更では表示中の行を保持し、絞り込みを選び直したときに一覧を更新します。一致する種類がない場合は「すべて表示」から戻れます。別のパックで保存した指定も表示し、確認中のパックの対象外であることを示します。パックをすべて削除した後も、保存済みの指定を確認・変更できます。パックの対象外の指定を解除した場合も、画面を閉じるかパックを切り替えるか「再調査」するまではその行を保持します。

各種類では保存済みの指定、適用中の設定による見本、下書きを保存した後の見込みを確認できます。パック画像を許可しても、パックの対応範囲や対象選択によって元の表示になる場合があります。名前パターンや共有クラスを経由するパック対象外の種類について、保存後の登録計画をこの画面の情報だけで確定できないときは「確認できません」と表示します。見本は代表ファイル名で計算し、個別のファイル名やExplorerの更新状況によって実際の表示が異なる場合があります。登録が変わった指定は、保存済みの内容を表示したうえで、再指定されるまで保護します。

ページ切り替えを使わず連続スクロールで全件を確認でき、再調査もできます。Home／Endで先頭／末尾へ、PageUp／PageDownで表示範囲を移動できます。通常の一覧では種類と理由を読み、「登録の詳細」のチェック付きトグルで関連付けクラスと登録位置を展開します。表示の切り替えと詳細の開閉では下書き・保存値を変更しません。長い値は省略表示し、「詳細をコピー」で完全な情報を取得できます。変更だけでは保存せず、「保存」または「保存して再適用」で確定します。未保存の変更があれば下部に表示します。戻る操作とEscでは下書きを破棄し、元の操作へフォーカスを戻します。調査失敗や保存失敗は画面へ表示し、保存失敗後も下書きを保持します。

判定では、パックの登録対象拡張子を有効な関連付けクラスへ解決し、各拡張子の元の画像指定・専用処理と確認済みの方針を調べます。保護する種類は拡張子単位で記録します。クラス内の対象をすべて保護する場合はクラスを登録しません。一部だけパックを許可した場合はクラスへShell拡張を登録し、実際のファイル名から保護を判定して、保護対象と未対応ファイルを退避済みの元処理・画像へ委譲します。拡張子自身の元指定も既存の退避情報へ保存し、共有クラスの画像で置き換えません。専用処理を画像指定より優先し、同種の指定では拡張子自身をクラスより優先します。拡張子なし・名前パターン用の`Unknown`も、拡張子単位の指定と分離します。調査・適用時に登録済み拡張子を確認し、表示ごとの総走査は行いません。読み取れない登録は変更前に停止します。

適用中の調査では変更記録にある適用前のHKCU値を使い、元値がなければHKLMの値を参照します。保存時には従来の登録整合性検査を行い、旧登録を復元してから新しい方針で再登録します。失敗時は以前の設定とパックへ復帰します。全種類が除外されたパックは登録を書かずに適用状態と除外理由を保存し、「Windows標準に戻す」で解除できます。外部ソフトによる後日の変更は次回の調査・明示適用で扱い、登録競合は従来の確認付き復旧に従います。

CLIは `protection show`、`protection set on|off [--dry-run]`、`protection exclusions <pack-id>` を提供します。JSONの `preserve_existing_icons` と `icon_exclusions` は翻訳しません。除外理由の識別子は `default_icon`、`icon_handler`、`protected_file_type`、`changed_registration` です。`resolve` とパック内の画像プレビューはテーマ・対象選択の照合結果であり、Windowsへの登録除外の確認には保護画面または `protection exclusions` を使います。

Shell用の形式4と管理用の形式4を使用します。個別の保護例外は管理用の `icon_protection_rules` に保存し、Shell用データには適用時の除外一覧も保存します。独立した復元記録は形式2で保護設定を保持し、形式1も読み取ります。設定と復元記録の非対応形式は拒否します。

### 拡張子のないファイルなどの表示

`Unknown`の保護は「拡張子のないファイルなど」という独立した項目にまとめ、ソフト名のグループから分離して一覧の先頭に表示します。見出しを省略せず、全パック共通の設定であることと、パックの名前規則に一致するファイルだけが対象になることを表示します。元アイコンの提供元は「登録の詳細」で確認できます。ソフトの一括指定と初期化は、この独立した項目の指定を変更しません。以前にソフト単位で保存した拡張子なしの指定も保持します。この項目で「全体設定に従う」を明示的に選ぶと、その個別指定と以前のソフト指定だけを解除し、共通の保護設定へ戻します。

見本には、パックに定義された拡張子なしの完全一致名・言語由来の名前から、画像を解決できる実例を選びます。現在と保存後の結果には、そのファイル名を添え、対象選択と保護を反映します。名前パターンしかなく実例を選べない場合は「ファイル名で確認」と表示し、仮の`sample`を未対応と判定した結果を代表例にしません。パックの許可ボタンも同じ実例の画像を使います。

選択肢の「パックのアイコンを許可」は置き換えの許可を示し、必ずパック画像になるという意味にはしません。名前規則に一致しないファイルや無効にした対象は元の表示を維持します。保護の既定値、保存キー、登録・競合・復元の方針は変更しません。

### 提供元と種類ごとの指定

一覧全体を一つのカードにまとめ、提供元間を細い線で区切ります。複数の提供元を同時に展開でき、展開内容は一段明るい面とします。提供元ごとにアイコン・左揃えの名称・表示中と全体の種類数・保護とパック許可の件数を表示し、それらと余白を含めた見出し全体のクリック、またはTabで選択後のEnterで開閉できます。見出しには独立した通常背景を付けず、閉じたときは内容との区切り線を表示しません。初めは展開し、画面を閉じるまで開閉状態を保持します。一覧直前の操作列の右端に「すべて開く」「すべて閉じる」を並べ、全提供元の内容を一度に開閉します。全提供元が開いているときは「すべて開く」、全提供元が閉じているときは「すべて閉じる」を無効にします。調査・処理中と対象がないときは両方を無効にします。閉じても下書きを保持し、見出しから再展開できます。開閉は保存する設定に含めません。提供元を特定できない種類は関連付けクラスごとに分けます。

展開内容の「このソフトの基本設定」に「元のアイコン」「パックのアイコンを許可」「全体設定に従う」の画像付きトグルを置きます。種類ごとの操作と同じ外観・クリック領域・キーボード操作を使い、選択済みの項目を押しても解除しません。個別指定があっても基本設定の選択表示を維持し、「個別設定」と件数を表示します。親の三択では個別指定を保持します。「全体設定に従う」は基本設定だけを解除します。独立した「このソフトの設定を初期化…」で基本設定と確認済みの種類の個別指定をまとめて解除できます。ソフト名・解除件数・下書きへの変更であることを警告し、キャンセル・Escでは変更しません。確定後は親が「全体設定に従う」、子が「基本設定に従う」になります。ほかのソフトの指定を保持し、保存するまで適用しません。一覧には確認するパックと関連付けを共有する種類のほか、別のパックで保存した指定を含めます。一括指定は調査済みの種類だけへ保存し、未知の種類へ上書き許可を自動で広げません。各拡張子には「元のアイコン」「パックのアイコンを許可」「基本設定に従う」の画像付きトグルボタンを置きます。画像・ラベル・余白のクリック、またはTabとEnter・Spaceで選択し、選択済みのボタンを再度押しても選択は外しません。拡張子の個別指定、提供元の一括指定、既定の方針の順に判定します。「基本設定に従う」は個別指定を解除して提供元の基本設定へ戻り、未指定なら全体設定に従います。

同じ関連付けクラスを共有する種類でも、個別指定はそれぞれ独立して適用します。共有先の保護を解除する必要はありません。クラスのアイコン処理へ介入しても、保護対象は退避した元処理・画像へ委譲します。`.lnk`・`.exe`と、その共有クラスへの登録は常に拒否します。保存・再適用・復元には既存の退避・競合検査・失敗時の復帰を使い、ファイル内容と既定アプリは変更しません。既存の設定ファイルは読み込みだけでは変更せず、再適用時に新しい判定で除外情報と退避情報を作り直します。

表示名は識別キーにしません。画像の資源ファイルまたは専用ハンドラーのモジュールを識別し、利用可能ならファイルの説明を表示します。画像素材が既定アプリの専用設置先の配下にある場合は、そのアプリ単位にまとめます。通常一覧には推定方法の注記を表示しません。Windowsの共有システムフォルダーから提供元アプリを推定しません。特定できない場合は「提供元不明」とし、既定で開くアプリとアイコンの提供元を混同しません。過去の設定を書き込んだソフトを断定する機能ではありません。

Windowsパッケージ形式の `@{PackageFullName?ms-resource://…}` は、Windowsの `SHLoadIndirectString` で表示名と画像資源を解決します。登録された `AppUserModelID` が参照元のパッケージファミリと一致する場合、パッケージファミリを正規化し、アプリ部分の大文字小文字は保持してそのアプリIDでまとめます。素材名や版の違いはグループを分けず、同じパッケージ内でも別のアプリIDは別のアコーディオンとします。名前は `ApplicationName`、見出しのアイコンは `ApplicationIcon` を使い、種類別の元画像は元の `DefaultIcon` を使います。アプリIDを確認できない場合は関連付けクラスごとに分け、名前を解決できない場合はパッケージ名へ戻します。壊れた参照の末尾の素材名をアプリ名として表示しません。

パッケージの識別や画像資源が変わった以前の許可は再確認します。素材単位の古い許可を、新しいアプリ全体の許可として自動移行しません。明示的にソフト単位の三択を選び直すと、確認した種類の古い指定を整理します。

例外には関連付けクラス、元の画像指定・専用ハンドラー、資源モジュールの所在・大きさ・更新日時、既定アプリの実行ファイルを結び付けます。内容が変わった場合や元の指定が消えた場合は例外を保護へ戻し、再指定を促します。提供元や関連付けの変更を受けて、以前の上書き許可を自動で移しません。再調査だけでは設定を保存しません。

共通の保護切替、一括指定、個別指定では取得済みの登録情報から表示だけを更新し、再調査・画像抽出を実行しません。外部登録の変更は「再調査」で取得します。保存・適用時には既存の競合検査を行います。

### 既存アイコンの見本

適用中は変更記録に退避した元の指定を使用し、本アプリのアイコンを元の画像として表示しません。提供元には、取得できた実行ファイルまたは資源モジュールの代表アイコンを添えます。この画像を各種類の元アイコンの代わりには使いません。画像資源の見本とパックの拡張子用見本を「元のアイコン」「パックのアイコン」として並べ、継承も含む三つの欄に同じ最小幅10remを設けます。選択中のタイルだけを枠・チェック・画像の通常明度で強調し、未選択の画像を減光します。「基本設定に従う」には個別指定を解除した場合の実効画像を表示し、その種類自身の保護を反映します。パック画像がなければ元画像、画像を取得できなければ警告アイコンを使います。基本設定や全体設定の下書きを変えると、再調査せず継承画像も更新します。説明はツールチップへ置きます。ファイル名によって画像が変わる種類では、パック側は `sample.<拡張子>` の代表画像です。

画像抽出は専用子プロセスで行い、全体を5秒で打ち切ってその子を終了します。外部COMハンドラーや関連付けの起動コマンドは実行しません。固定ローカルドライブ上の64 MiB以下の資源を対象とし、一回の調査で128種類の異なる資源、要求JSONは1 MiB、出力は32×32のPNGで一枚64 KiBまでとします。同じソフトに新旧の資源指定が混在する場合、取得できた代表画像を優先します。同じ資源は共有し、提供元の代表画像を種類別の画像より先に抽出します。パッケージのPNGは4096×4096・復号時64 MiBまでとし、縦横比と透明度を保って32×32へ収めます。間接参照の解決は調査ごとに最大256件を保持し、アプリ登録値は一つ64 KiB、参照と解決結果は32768文字のバッファで制限します。一時画像は画面を閉じるか再調査で置き換えた時に破棄します。

専用ハンドラー、`%1` によるファイル固有画像、ネットワーク上の素材、上限超過、取得失敗には代替の警告アイコンを同じ幅の欄へ表示し、取得できない理由をツールチップに示します。見本の取得失敗だけで保護を解除しません。Shellのファイル表示経路へ画像変換を追加しません。

## 再取り込みと削除後の下書き

別バージョンを別IDで取得した場合は、自動で設定を移しません。取得済みパックの「別バージョンの設定を確認…」からコピー画面へ移動できます。提供元・拡張・テーマが同じ別バージョンを先に並べ、コピー元と引き継ぎ先の版、一致・追加・削除の件数を示します。「追加・削除された対象を確認」で対象名を展開できます。表示名が同じだけの別テーマを同一テーマとは扱いません。

「一致する設定を引き継ぐ」はコピー元の保存済み設定だけを下書きへ移します。コピー先だけの対象への指定は保持し、削除された対象はコピーしません。保護対象は引き継ぎません。取り消し・保存・適用の契約は通常のコピーと同じです。旧版の削除や適用中のパックの変更は行いません。

パック詳細の各見本にある「表示予定を確認」から、同じファイル名の比較画面へ移動できます。見本は保存済みの対象選択だけを反映し、比較は保存済み・下書きそれぞれに既存アイコンの保護を含めます。対象選択に未保存の変更があれば比較の予定側へ反映します。保護の調査中・確認不能時に、パック画像が実際に使われると断定しません。

同じ識別子のパックを再取り込みした場合は、最新の対象定義に下書きと取り消し履歴を照合します。消えた対象の指定は取り除き、取り消しによって復活させません。残る対象の未保存指定は保持し、保存時に最新の定義へ適用できる状態にします。選択中の行や詳細の対象も最新の一覧へ揃えます。

パック削除後はその下書き・取り消し履歴・関連する表示選択を破棄し、同じ識別子の再追加で復活させません。定義が変わらない画面移動・言語変更・競合確認では未保存指定を保持します。取り込み・保存が失敗した場合も、実際に保存されている定義と整合する下書きを保持し、再試行できます。下書きを永続化する形式は追加しません。

## 適用中パックの選択反映

適用中パックの対象編集では「変更を適用」を唯一の確定操作とし、選択反映の後に同じパックを再適用しません。未適用パックでは「選択を保存」と「この設定で適用」を分け、取得や保存だけで表示を変更しません。全対象を無効にして変更を適用した場合は登録を解除します。失敗時は処理結果を示し、未保存の下書きと復元記録を保持して再試行できるようにします。

### 作業面の階層

カテゴリと対象一覧は背景から一段上げた同じ階層の作業面とし、外側の間隔を揃えます。比較の保存済み・予定は同じ幅の補助面へ、コピー元はパックごとの補助面へまとめます。大量の対象行は従来の一覧として扱い、一件ずつカード化しません。補助面の追加でスクロールの所有者や保存・適用・戻るの契約を変更しません。

## 開発者向けのおすすめ設定

保護画面の表示切り替え「変更内容」では、共通設定と固定帯の保存・破棄を維持して、中央の一覧を比較表示へ切り替えます。「比較する内容」は保存済みと現在の下書きの差（保存予定）と、直前のおすすめ操作の記録から選べます。操作記録を表示中も保存対象は現在の下書きです。全体の既定は別項目とし、拡張子の保護解除・追加・指定更新を数えます。各行に対象、変更前、変更後、変更の種類を示し、個別指定、基本設定への継承、実効保護、確認情報のみの更新を区別します。「詳細」の画像比較は保存予定に限定し、記録へ現在の画像を流用しません。「設定を開く」は提供元を展開して該当する個別設定へ移動し、下書きを保持します。調査中・調査失敗を変更0件とは扱いません。表示や移動だけでは保存・再適用しません。保護の許可は対象選択やパックの対応状況による実際の表示を保証しません。

「おすすめ設定」は開発者向けの一括編集です。全体の保護をオンにし、調査済みのVS Code提供元（実行ファイル `Code.exe`）をパック優先へ変更して、その種類の個別指定を継承へ戻します。ほかの提供元でも、開発言語、Webのソース類、ビルド・開発ツールの拡張子をパック優先にします。Web分類のフォント（woff・woff2・ttf・otf）は除きます。JSON・JSONC・JSON5・JSONL・YAML・YML・TOML・XML・INI・properties・env・Markdown（md・mdx）も対象です。分類は同梱表、追加対象は `crates/icon-core/src/recommendations.rs` に従います。

対象の個別保護は置き換え、対象外の指定と別ソフトの基本設定を保持します。検索や絞り込みによらず調査済みの種類へ反映します。`.ts`・`.tsx`・`.mts`・`.cts` を含み、同じ拡張子の動画も対象です。共有クラスの `.m2ts` 等へは許可を広げません。固有名から拡張子全体や `Unknown` を許可せず、`.lnk`・`.exe` と要確認の登録は保護を維持します。

ボタン一回で下書きと表示予定を更新し、追加の選択画面や確認は挟みません。通常の三択で調整し「保存」「保存して再適用」で確定します。反映だけでは保存・再適用・再調査・画像抽出を行わず、戻ると破棄します。繰り返しても同じ設定になり、調査中・調査失敗・設定無効・処理中は実行できません。保存形式と起動時動作は変えません。
