# 0.1.0 — Initial release overview

FileHue 0.1.0 was released on November 5, 2026 (Japan Standard Time; November 4 UTC). Download the unsigned Windows x64 ZIP and `SHA256SUMS.txt` from the [v0.1.0 release page](https://github.com/YukiWorks432/FileHue/releases/tag/v0.1.0). This document describes the initial release features and limitations. See the [changelog](https://github.com/YukiWorks432/FileHue/blob/main/CHANGELOG.md) for changes between versions.

The GUI, CLI, and Shell DLL are not code-signed. SmartScreen may show a warning, and Smart App Control or organizational policies may prevent execution. Check the distribution source and `SHA256SUMS.txt`. SHA-256 verifies file contents; it is not a Windows publisher signature. Installing a self-signed certificate or broadly disabling Windows protection is not a setup requirement.

## Features

- VS Code-style filename and extension icons in Windows 11 x64 File Explorer.
- A Japanese/English GPUI GUI for reviewed-pack downloads, local imports, previews, applying and switching packs, restoration, and removal, plus an auxiliary CLI.
- Target selection by category, filename, or extension, with existing-icon protection by provider and file type. `.lnk` and `.exe` always remain protected.
- Preservation of file contents and default applications, Windows fallback for unsupported types, bounded download/extraction/conversion, and saved registration recovery information.

## Setup and limitations

Follow the [usage guide](../usage.en.md). Keep the executables and Shell DLL together and install the required Visual C++ runtime. Explorer may need restarting after the first application. Restoration cannot recreate original artwork that another application has already removed.

To update the application, follow the [update procedure](../usage.en.md#updating-filehue): restore with the old version before starting the new version from a separate folder. Pack updates are separate. The guide also describes [removal and retained data](../usage.en.md#removal-and-settings).

Windows 10, ARM64, system-wide installation, font-based themes, and all third-party handlers or display scales are outside the supported scope. The application does not add a thumbnail provider. ANSI-only icon handlers have not been verified. COM-path performance measurements do not measure all Explorer interactions.

Protected types, disabled targets, or theme definitions may prevent a dedicated icon from being shown. Review exclusions and previews in the GUI. If recovery is needed, follow the [recovery guide](../conflict-recovery.ja.md) (Japanese) and the English recovery section of the [usage guide](../usage.en.md#recover-from-registration-conflicts). Do not delete recovery records manually.
