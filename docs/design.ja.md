# GUIのデザイン方針

GUIはGPUI / GPUI Kitで実装する。操作の種類・まとまり・現在の状態を通常表示から読み取れるUIを目指す。製品固有の原則と例外は[デザイン規約](ui-design.ja.md)、判断と検証の手順は[デザインスキル](../.agents/skills/project-ui-design/SKILL.md)を正本とする。

## 原則と実装の対応

| 判断する内容 | 本製品の方針 | 実装・契約の所在 |
| --- | --- | --- |
| 操作の種類 | 画面切り替え・設定選択・処理実行・開閉を区別する | デザイン規約の操作分類 |
| 面と所属 | 独立した作業をカードにし、内側の詳細は補助面へ置く。Fluid Functionalismに基づいて背景から明度を上げる | `theme::card`、`theme::inset`、共通テーマ |
| 押せる範囲 | 通常ボタンは親から区別できる不透明な背景か意味色、小さな影を持つ | `theme::button`、`disabled_elevated` |
| 選択と結果 | 方針の選択、実際に使う画像、キーボードのフォーカスを分ける | 画面別の操作契約とGPUI試験 |
| 画像と文字 | 画像の有無で列幅を変えず、操作名と重要な状態は通常表示へ残す | アイコン提供元と保護設定の規約 |
| 余白 | 関連情報を近づけ、独立した操作を離す。配置元と内容で余白を二重化しない | Kitの相対尺度とデザイン規約 |

具体的な色値と配色の割り当ては[theme.rs](../apps/icon-manager/src/theme.rs)に集約する。パック素材の色はUIの状態色と分離し、パックを変えても操作の意味を維持する。平坦なアコーディオン見出しなどの例外はデザイン規約の適用条件に従う。

## 外部資料と検証

外部資料は[固定版と参照手順](design-references.ja.md)から読み、製品の規約と異なる点を区別する。本文・翻訳・図版・コード例は同梱しない。部品のAPIは採用したCargo.lockの版で確認する。

操作はGPUIのtest-support、見た目は実画面または描画画像で確認する。日英、明暗、狭い幅、文字拡大を含め、画像を取得しただけで確認済みとしない。共通テーマの変更では影響する全画面を確認する。提出時の報告は[貢献手順](../CONTRIBUTING.md)に従う。

この方針は公開資料と本製品の規約・ソースだけで読める内容として維持する。権利表示が必要な原文や素材を、参照の整理を理由に削除しない。公開時にも、文書・ソース・配布物から参照の閉じた構成を維持する。
