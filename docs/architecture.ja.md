# アーキテクチャ

Rust製のテーマ処理、取得、Windows統合と、GPUI / GPUI Kit製GUI、補助CLIを分離する。ここには採用中の構成と保存・登録の安全境界を記述する。依存版はCargo.lockを正本とし、未対応範囲は[要求仕様](requirements.ja.md#対応範囲と配布方針)に従う。

## 構成と責務

| パス | 責務 |
| --- | --- |
| `crates/icon-core` | テーマ解析、素材検査、ICO変換、名前解決、選択と復元記録の規則 |
| `crates/icon-catalog` | 確認済み配布物の取得、ハッシュ照合、安全な展開 |
| `crates/icon-windows` | ユーザー単位の保存、関連付け照会、登録と復元 |
| `crates/icon-manager-service` | 管理ロック、取得・取り込み・選択保存・適用・復元の共通処理 |
| `crates/icon-shell` | `IPersistFile` / `IExtractIconW` によるCOM DLL |
| `crates/thumbnail-core` | 埋め込みプレビューの抽出とSVG描画 |
| `crates/thumbnail-shell` | `IInitializeWithStream` / `IThumbnailProvider` によるサムネイルDLL |
| `apps/icon-manager` | GPUI製GUI。主要操作、日英表示、進捗と復旧画面 |
| `apps/icon-cli` | GUIと共通管理処理を使う `file-icons.exe` |

重いテーマ解析と描画変換を導入段階へ分離し、Explorer内の処理量を抑える。ユーザー向け文言を翻訳資源に分離し、設定やパックの識別子は言語に依存させない。

取り込みの`import_observed`は中断確認に加え、使用する画像定義の総数と変換・検証を完了した件数を通知する。従来の`import_controlled`も同じ処理を使う。取得・取り込み側の`Progress`がテーマ番号と件数を一貫した組として保持し、GUIは既存の更新タイマーで読む。進捗通知は書き込み・出典の公開や設定保存の契約を変えず、既存ICOの再検証も省略しない。

GUIはExplorer内で動くShell拡張から分離する。UIの原則と検証は[GUIとデザインの参照方針](design.ja.md)に従う。

サムネイルはアイコン処理と別のDLL・設定・復元記録を使う。形式ごとのCLSIDと拡張子単位の登録だけを扱い、共有ProgIDの登録を分配する場合は共有先と外部参照を照合する。変更前の値を先に記録し、復元時は共有する組全体を照合する。ユーザー側の未選択種類は元の提供元へ戻し、マシン側の共有登録は未検証として拒否する。失敗した記録は保持する。表示条件は[内容のサムネイル](thumbnails.ja.md)を参照する。

関連付けの参照調査では、日本語などを含む正常なアプリ登録も扱う。クラス名と登録キーの識別にはアイコン側と同じUnicodeの小文字化を使い、非ASCIIの大小文字差がある未選択の共有先も同じ組に含める。登録・復元用の綴りと生の値は保持し、循環、参照数、書き込み先の制限は維持する。

GUIの通常起動では、管理ロックの取得と設定読み込みを描画基盤の初期化と並行して進める。画面を構築する前に結果を受け取り、ロックと検証済み設定を画面へ引き渡す。操作可能な仮の設定や、後から設定を差し替える段階は設けない。読み込み失敗時の復旧案内と、ロックを取得できない場合の操作制限は同期起動と同じである。

CLIの対象編集・コピーは、同じ管理ロック内で一度読んだ設定から変更案を作り、その写しで対象の妥当性と保存・登録の前提を確認する。操作をまたぐ設定キャッシュは持たず、保存時の原本照合と登録競合の検査を保持する。検索条件の正規化は入力ごとに行い、対象の走査中は再変換しない。

パックごとに識別子、版、出典、権利表示を保持する。VS Code拡張のプログラムは実行せず、宣言された定義と素材を入力として扱う。正規化したパスが拡張フォルダー内にあることを確認し、入力サイズを制限し、変換失敗時にはパックの選択状態を変更しない。対応形式と安全上限は[パック取得](pack-downloads.ja.md)を参照する。

## 既存アイコンハンドラーとの共存

既存アイコンの保護設定は既定で有効とし、画像指定または専用ハンドラーのある種類の元アイコンを維持する。すべての対象を保護する関連付けは登録計画から除外する。判定と除外理由の正本は[既存アイコンの保護設定](target-selection.ja.md#既存アイコンの保護設定)である。以下のテーマ優先と元ハンドラーへの委譲は、明示的な例外指定などで保護を解除した種類に使う。

共有クラスに対するShell拡張の登録と、拡張子ごとのアイコン保護を分離する。一部の種類だけを許可した場合も、保護対象と未対応のファイルは退避した元ハンドラー・画像へ委譲する。元の画像と専用処理の辞書はクラス名に加えて`.拡張子`のキーを保持し、拡張子側にある指定を失わない。専用処理を静的な画像より優先する。`.lnk`・`.exe`のクラスはこの仕組みへ登録せず常時除外する。

既存ハンドラーの識別子を保存し、テーマ対象のファイルはパックの画像、対象外のファイルは元のCOMへ委譲する。元の登録は変更前の生データで復元し、利用者が後から行った変更は上書きしない。

関連付けクラスは、復元記録の既存の重複検査と同じ小文字化による識別で集約する。APIの戻り値の綴りだけが異なっても、一つの登録先へ二重に書き込まない。通常表示への委譲も同じ識別を使い、旧記録に残る元の綴りを読めるようにする。登録キーの綴りと変更前の型・生バイトは復元用に保持する。Windows全体のUnicode照合規則を新たに定義するものではない。

`AssocQueryStringW` が返す `Applications\<実行ファイル名>.exe` は正常な読み取り対象として認識する。ルート名と拡張子の大文字・小文字は区別せず、実行ファイル名にパス区切りや無効な文字を許可しない。この関連付けを共有する種類は常時保護し、保護の共通設定や例外より優先して登録計画から除外する。アプリ登録全体を書き換える対応は行わず、ほかの種類への適用を継続する。復元記録が書き込める範囲の検査は緩めない。

ShellLinkを使う子プロセス専用の結合試験とABI試験で検証する。実Explorerでの共存は[受け入れ手順](explorer-acceptance.ja.md)で別に確認する。ANSIのみのハンドラーとの互換性は未確認である。

## 復元情報の保存境界

通常の設定が壊れても表示と解除の情報を失わないよう、レジストリ変更前の記録を独立したファイルに先行保存する。復元では現在値の照合を維持し、解除済みの設定保存後に記録を除去する。設定が読めないGUIからは記録による解除だけを許可し、壊れた設定自体は別ファイルへ退避する。処理順序と中断時の保証は[開発と検証](development.ja.md)を参照する。

確認付きの競合復旧は `icon-windows::conflict` に集約し、管理サービスの同じロックをGUIとCLIで使う。先に解除先の仮想的な写しから最終登録計画を作り、解除と再適用の途中で未確認の計画を追加しない。元の設定と観測値を退避し、`conflict-operation.json` に元の設定・解除先・予定を先行保存する。各値の照合と書き込み、設定保存、全値の検証、通常解除用の記録の確定を終えてから途中記録を除去する。未完了時は通常の変更を止め、最新の観測値へ結び付けた新しい確認で続ける。外部変更と本アプリが途中で書いた値を区別し、解除先を維持する。保存順序と利用者向け契約は[登録競合の復旧](conflict-recovery.ja.md)を参照する。

## Shell DLLの配置

ビルド出力や配布元への直接登録を避け、ユーザーデータ配下へ内容ハッシュ別に配置したDLLを登録する。同じ内容は検証して再利用し、異なる内容は新しい保存先を使う。配置済みのファイルを上書きせず、Explorerによるロードと開発中の再ビルドを分離する。登録解除後の整理はGUIから別操作で行う。設定・独立した復元記録と、利用者側・有効クラス側のCOM登録を確認し、残っている間は削除しない。所有する保存先と内容の一致を同じOSハンドルで検証してから削除する。使用中・未知の内容・リンクは保持し、走査と読み取りには上限を設ける。現時点の検証と残作業は[開発と検証](development.ja.md)を参照する。

## パック切り替え

切り替え前に現在の登録値を照合し、選択先と戻す版のDLLを確保する。現在の登録を元のWindows状態へ戻してから新しいパックを適用し、失敗時は新しい登録を解除して以前のパックを再適用する。復帰の成功と切り替え自体の成功を区別し、復元できなかった場合は未完了の記録を保持する。処理中の停止を含む保証範囲と試験は[開発と検証](development.ja.md)を参照する。

## 関連付け照会の再利用

未対応名の通常表示では、現在のProgIDをWindowsへ照会し、保存済みの元の表示・ハンドラーを選ぶ。同じ拡張子についてこの照会を繰り返す時間が大きかったため、Shell内で通知付きのキャッシュを用いる。

利用者とマシンの `Software` キーを、読み取りの通知権限だけで監視する。Classes、FileExtsのUserChoice、ポリシー等を含む上位の監視とし、細いキーの作成・削除・再作成も変更として扱う。ほかのソフトによる無関係な変更でも無効化されるが、古い関連付けを長く返すことを避ける。待機用の常駐スレッドは作らず、各照会時にイベントを非待機で確認する。

通知を観測した場合は全件を捨て、通知を再登録する。`REG_NOTIFY_THREAD_AGNOSTIC` を使い、登録したCOM呼び出しスレッドが終了しても監視を継続する。監視の初期化や再登録が失敗した場合は再利用を止め、通常のWindows照会を続ける。照会の失敗をキャッシュしない。最大256件、キーと結果それぞれ1,024バイトまでを保持し、ASCIIの拡張子の大文字・小文字を区別しない。

保持期限は1秒とする。[RegNotifyChangeKeyValue](https://learn.microsoft.com/en-us/windows/win32/api/winreg/nf-winreg-regnotifychangekeyvalue)が通知しないRegRestoreKey等の変更についても、次の期限切れの照会で取り直す。これはすべての変更を常に即時反映する保証ではない。

Windows側への照会中はキャッシュのロックを保持しない。照会中に通知や解放があった場合、その照会が返した古い結果を新しいキャッシュへ保存しない。COMがアンロード可能になった場合は、監視用のキー・イベントと設定の解析結果を解放してから返す。処理中のオブジェクトやサーバーロックが残る場合は解放しない。

## 管理設定とShell実行用データの分離

形式4のsettings.jsonは適用中のテーマと登録・復元情報だけを保存し、形式4のsettings.library.jsonへ全パックの一覧と言語・削除保留を分ける。Shellは管理用ファイルを読まない。適用情報に変化がなければShell用ファイルを置換しない。各JSONは上限付きで直列化し、一時ファイルへ同期書き込みしてから置換する。非対応形式は読み込みと通常保存を拒否し、原本を保持する。独立した復元記録は形式1・2を読み取り、レジストリ変更前に先行保存し、復元完了まで保持する。

テーマ規則は構築後に直接変更できない。規則全体の置換時に名前の正規化と競合・パターンを検証し、成功したときだけ照合キャッシュごと更新する。保存形式の読み込みにも同じ構築経路を使う。

## 適用対象の利用者設定

取り込み済みテーマの規則は変更せず、テーマ識別子ごとのSelectionを管理用設定へ保存する。Shell用の写しには適用中の選択だけを入れる。共通管理処理が対象識別子を照合し、GUIとCLIの双方から同じ更新処理を呼ぶ。カテゴリは設定の別階層ではなく、共通の対象分類と一括編集の入口である。

Shellは名前解決前に選択を確認し、無効なら元のハンドラーへ委譲する。パターンの照合器は設定の読み込み後に再利用し、選択変更時に作り直す。適用中の選択変更は選択対応の同梱DLLを使う再適用として扱い、従来の切り替え失敗時の復帰を維持する。詳細と操作契約は[適用対象の選択](target-selection.ja.md)を参照する。

GUIの対象列挙は現在開いているパックについて保持し、設定の再読み込み・再取り込み時に作り直す。描画はパックと下書きを借用し、絞り込み後の対象も参照で扱う。保存・適用する選択の複製は確定操作時に行う。取り消し履歴は変更した識別子と直前の個別指定だけを32操作分保持し、再取り込み後は未対応の識別子を履歴からも除く。

保護画面は調査済みの行から拡張子・提供元・共有クラスの索引を組み立て、方針変更時に保護件数と見本を更新する。保護一覧には別パックの保存済み指定も含める。対象画面では実際の登録計画と同じ範囲を調査し、一覧に追加した行が適用予定の判定を広げないようにする。画面間を移動すると、それぞれの範囲を再調査する。Windowsの登録調査では、その呼び出し内だけで全件列挙と関連付けの照会結果を共有する。次回の調査、保存、適用へ結果を持ち越さず、登録変更の検出と復元記録の照合を維持する。

対象画面の検索結果、検索結果全件の一括操作対象、カテゴリ件数と変更件数は同じ表示状態で再利用する。検索入力、カテゴリ・状態の切り替え、下書きの編集・取り消し・コピー、設定の再読み込み、保護調査と方針変更で無効化する。入力イベントの通知前に描画される場合にも、現在の検索文字列と照合する。一括操作用の識別子は共有して保持し、表示中の100件に範囲を狭めない。ページ内では可視範囲の行だけを構築し、幅・文字サイズ・言語・展開内容の変化に合わせて再測定する。未測定の行にも文字サイズに応じた高さの見積もりを与え、画面外の対象をスクロール範囲から落とさない。実際の高さは折り返しや展開内容の測定結果で更新する。固定したGPUI版では初回と一覧幅の変更時に見積もりが消えるため、子要素の配置後に補い、初回表示と幅変更直後も末尾への到達を維持する。

同じ調査内では、画像資源の識別・表示名・更新情報、既定アプリとの資源配置関係、同じクラスと参照値のパッケージ情報も共有する。資源の安全検査と登録ごとの指紋は保持する。調査完了後の並べ替えと件数算出にも索引を使う。登録情報をGUIへ反映してから、期限と件数上限のある子プロセスで見本を生成する。見本の読み込み中も取得済みの方針を編集できる。見本の失敗は登録調査の失敗と区別し、前の調査・閉じた画面から遅れて届いた結果は採用しない。

登録計画では、保護調査で取得した関連付けを登録先の集約にも再利用する。比較用の小文字化と、復元・書き込み用の元のクラス名を区別し、同じ計画内で拡張子の関連付けを再照会しない。次の計画・保存・適用には持ち越さない。

パックの見本は保存済み選択を借用して解決する。設定コピーの候補表示では対象外の件数だけを算出し、コピー後の選択全体を保持しない。確定時に最新のコピー元とコピー先の下書きから結果を組み立て、変更した指定を取り消し履歴へ残す。表示・コピーだけでは保存や適用を行わない。

## 復元記録の登録範囲

通常復元、破損設定からの解除、確認付き競合復旧は、復元記録の全件を検証してから登録の書き込み・キー削除・設定保存を開始する。DefaultIcon、IconHandler、本アプリのCOM登録だけを許し、起動設定・他のCOM登録・無関係な作成キー・重複した値の記録を拒否する。不正な項目が有効な項目の後にあっても、一部だけ復元しない。独立した復元記録も読み取り時に同じ境界で検査する。拒否時は設定と復元記録を保持する。

旧版が登録した `.lnk`・`.exe` の解除は新規適用の除外と区別し、記録した元の値を型・バイト列ごと復元する。外部変更との競合時停止と、保存失敗後の再試行は維持する。

## 破損設定の保存と退避の境界

通常保存はShell用設定とパック一覧の本文まで解析し、破損・非対応形式を上書きしない。両ファイルがない場合は新規作成する。破損設定からの解除は独立した復元記録を検証し、両原本の完全な退避を作成してから登録を変更する。退避は1ファイル16MiB以内とし、上限を1バイトでも超えた入力、読み取り途中の増大、退避失敗では登録を変更せず原本と復元記録を保持する。切り詰めたコピーを完成した退避として残さない。

通常保存の検査を省略できるのは、完全な退避を作成した明示復旧の内部経路だけである。保存直前に退避時の原本と照合し、変更されていれば置換せず再試行を案内する。上限を超える原本はこの復旧方法では解除できず、元ファイルを保持したまま別途の復旧判断を必要とする。
