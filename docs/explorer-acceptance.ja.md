# 実Explorerでの受け入れ手順

0.1.0の完成判定では、[要求仕様](requirements.ja.md#010の受け入れ条件)の各項目を実Explorerで確認する。以下は検証手順であり、合格記録ではない。GPUIの操作試験、隔離したCOM試験、実Explorerの受け入れは分けて記録する。

## 検証対象と環境

復元可能なWindows 11 x64環境を使う。開発PCへの登録は利用者が明示的に許可した後だけ行う。適用対象は検証用フォルダーに限定されず、選んだパックに対応するファイルの表示全般へ影響する。既定アプリやファイル内容は変更しない設計だが、実機の確認を省略しない。

検証用ZIPを展開し、[使い方](usage.ja.md#起動前の準備)に従う。実行ファイルとDLLを隣接させ、ZIP外のmanifest.jsonと権利確認記録に対して全ファイルを照合する。検証中はDLLの差し替えや再ビルドを避ける。公開承認や署名を得たリリースではない。

記録には、Windowsの版とビルド、CPU、画面の倍率、実行ファイル・DLL・ZIPのSHA-256、ソースコミット、パック名・版・テーマ識別子、実行日時を含める。画面とログは管理対象外の `work/` 配下へ保持し、共有前に個人パスや関連付け情報を確認する。パックを取得しただけの状態と、適用した状態を区別する。

## 公開前・Shell変更時の自動検証

Windows 11 x64の通常権限のターミナルで、対象コミットのソースから`just test-shell`を実行する。Shellの登録・保護・委譲・復元やWindows API依存に影響する変更時も対象とする。専用の設定とHKCUキーを使う隔離試験であり、通常のユーザー設定へ登録する操作ではない。

公開候補は、対象コミットのソースから`just verify-release --public-candidate --archive <候補ZIP> --report <新しい報告書>`を実行し、同梱DLLのSTA/MTAを含めて確認する。候補ZIPのハッシュと報告書の`shell_sta_mta=passed`を照合する。通常CIはこの試験を省略して`not-run`を記録するため、公開前の合格記録として読み替えない。自動試験の成功後、以下の実Explorer確認へ進む。

## 適用前の記録

検証専用の異なる二つのフォルダーに、Cargo.toml、settings.toml、package.json、data.json、README.md、notes.md、sample.rs、拡張子なしのDockerfile、対応しない拡張子のファイルを置く。PNG画像も置き、通常のアイコンとサムネイルを記録する。既存の利用者ファイルは試験のために書き換えない。

作成したファイルのSHA-256、対象拡張子の既定アプリと開くコマンド、既存アイコンハンドラー、詳細表示と大アイコン表示の画面を保存する。第三者ハンドラーが存在する場合は名前とCLSIDも記録する。既定アプリは設定画面の表示と関連付けの照会結果を照合し、ファイルを開く試験では信頼できる検証用ファイルだけを使う。

既存の本アプリの適用や復元要求がある場合は、先にそれを解決する。独立した復元記録と設定の保存場所を確認してから始める。初期化のために記録を削除してはならない。

## GUIとパック取得

日本語で一覧を開き、公式パックの作者、版、出典、利用条件を確認する。ダウンロードの中断と再試行、完了後にも未適用であることを確認する。英語へ切り替え、状態とエラーが切り替わることを確認する。言語選択後はGUIを終了・起動し、選択が保持されることも確認する。

専用アイコン三組の比較には、定義に違いを持つテーマを選ぶ。Catppuccin Icons 1.26.0のcatppuccin-mochaには、Cargo.toml / settings.toml、package.json / data.json、README.md / notes.mdの三組に別々の素材の定義がある。取得後のプレビューと実際のアイコンを照合する。別のパックで同じ素材が定義されている組を、異なるものと判定しない。

## 適用と表示

GUIで「適用する」を選び、適用中の表示と復元操作を確認する。初回の表示更新に要した時間と、操作中の停止・エラーの有無を記録する。更新されない場合はF5で再表示し、その必要があったことを記録する。初回登録が反映されない場合は、コピー等の処理を終え、利用者がExplorerを再起動してフォルダーを開き直す。検証者が開発PCで再起動する場合は利用者の許可を先に得る。再起動の有無と前後のプロセスを記録し、単なるウィンドウの開き直しと区別する。アイコンキャッシュの全削除は通常手順に含めない。

次の観点を二つのフォルダーで確認し、画面を残す。表示される画像だけでなく、各ファイル名との対応を記録する。

| 観点 | 確認内容 |
| --- | --- |
| 名前と拡張子 | 三組の専用アイコン、通常のJSON・Markdown・Rust、拡張子なしの名前 |
| 表示サイズ | 詳細、小、中、大、特大。ぼけ、欠落、別名への取り違えがないこと |
| 新規作成と名前変更 | 新しいJSONを作り、package.jsonへ変更して専用表示へ変わること。変更を戻すこと |
| 適用範囲 | 別フォルダーでも追加設定なしで同じ規則を使うこと |
| 通常表示 | パックで未定義の名前・拡張子が適用前の通常表示を維持すること |
| サムネイル | PNGのサムネイルを維持し、テーマで定義されたアイコンと混同しないこと |
| 共存 | 記録した第三者ハンドラーが担当するテーマ未定義のファイルで表示を維持すること |
| 既定アプリと内容 | 作成・改名した試験以外のSHA-256、既定アプリと開くコマンドが適用前と一致すること |

GUIは日本語・英語と使用する画面倍率で、文字の見切れ、操作部品の重なり、スクロール、キーボードのフォーカスも確認する。test-supportの操作成功だけを描画品質の証拠にしない。

## 切り替え・復元・削除

別の取得済みパックへ切り替え、適用中の表示と実Explorerの画像を確認する。切り替え前の素材を使用中に削除しないことも確認する。失敗時には詳細と復元記録を保持し、別操作へ進む前に状態を確認する。

「Windows標準に戻す」で復元し、適用前の表示、既定アプリ、ファイルのSHA-256、対象登録の生の値とキー構造を照合する。適用前からあった空キーも保持する。残った記録を手動で消して成功と判定しない。

復元完了後、未使用のパックを削除し、元の読み込みフォルダーを保持することを確認する。「不要なアプリ用ファイルを整理」で配置済みDLLを整理する。Explorerが保持して削除できない場合は、使用中と分かる案内を確認する。利用者がアプリを閉じるかWindowsへサインインし直した後に再試行し、管理領域外の原本を保持することを確認する。

## 本体の更新

[使い方の更新手順](usage.ja.md#アプリ本体の更新)を、保存形式の互換性を確認した二つの配布物で試す。それぞれのソースコミット、ZIP・実行ファイル・DLLのSHA-256と展開先を記録する。検証前の設定・パック・復元記録は独立して退避し、退避物を現行データへ上書きしない。

旧版でパックを適用した状態から復元し、対象登録を照合して旧版を終了する。新版を別フォルダーに展開し、取得済みパック、対象選択と保護設定が保持されていることを確認して再適用する。実Explorerでアイコン、試験ファイルのSHA-256と既定アプリを照合し、登録先のDLLとハッシュを記録する。両版のDLLが同一なら、その事実を記録し、異なるDLLへの差し替えを確認したと扱わない。

新版でも復元とDLLの整理を確認する。開始前に利用者がパックを適用していた場合は、検証後に元のパックと設定へ戻し、その結果を確認する。競合、互換性の欠如、操作を完了できない場合は記録と退避物を保持し、実施できた範囲と未確認の範囲を分けて報告する。

異常系は専用の検証環境で、正常時の復元を確認してから行う。設定の破損・消失時には独立した復元記録から戻せること、他のアプリが変更した登録は上書きしないこと、変換失敗や不正な配布物が適用状態を変えないことを確認する。通常プロファイルの設定や利用者の登録を、試験目的で破損させない。

各行に対象成果物と結果を結び付け、未実施・不合格・判定不能を残す。全項目の根拠が揃ってから、その候補の受け入れ結果をまとめる。要求仕様の基準自体を合格記録へ書き換えない。公開はその後の別の承認である。
