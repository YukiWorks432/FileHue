# 要求仕様

本製品が満たす要求と、公開候補を確認する受け入れ基準を定める。現在の動作は[現行仕様](current-specification.ja.md)、確認の実行方法は[開発と検証](development.ja.md)と[実Explorerの受け入れ](explorer-acceptance.ja.md)を参照する。本書は過去の合格記録を収録しない。

## 目的と確定事項

正式名称はFileHue、公開先は`YukiWorks432/filehue`とする。初回0.1.0はWindows 11 x64向けの未署名ZIPで配布し、GUI・CLI・Shell DLLへ自己署名や仮署名も付けない。公開候補の生成・検証と人による公開許可を分け、詳細は[配布手順](distribution.ja.md)に従う。

Rustで、Windows 11の標準エクスプローラーにVS Codeのファイルアイコンテーマを適用する。別のファイルマネージャーを必要とせず、開発用ファイルを識別しやすくする。ファイルの内容と既定のアプリを変更しない。

特定ディレクトリへの限定やファイル単位の手動操作を必要とせず、エクスプローラーで表示する対象ファイル全般へ適用する。詳細、小、中、大、特大の各アイコン表示を対象にする。新規作成、名前変更後も自動的に規則を適用し、同一ファイル名にディレクトリごとの設定を要求しない。

## アイコンの解決

既存アイコンの保護に該当する種類はテーマを適用しない。保護されない種類の優先順位は、ファイル名の完全一致、拡張子の一致、Windowsの通常のアイコンの順とする。テーマで未定義の専用アイコンは存在するものと仮定しない。

| 分類 | 対象例 |
| --- | --- |
| Web | .html、.css、.js、.jsx、.ts、.tsx |
| データ・設定 | .json、.yaml、.yml、.toml、.xml |
| 文書 | .md |
| プログラミング | .rs、.go、.zig、.py、.c、.cpp、.h |

対応拡張子はテーマ定義に従う。上記は固定の対応一覧ではない。

| ファイル名 | テーマで定義されている場合の専用アイコン |
| --- | --- |
| Cargo.toml | Cargo |
| package.json | npm / Node.js |
| tsconfig.json | TypeScript |
| README.md | README |
| AGENTS.md | 専用アイコン |
| rustfmt.toml | Rust関連 |

比較はUnicodeの小文字化を使い、複合拡張子は同じ照合段階内で長いものを優先する。直近の親フォルダー条件、言語由来の補完、パターンとの優先関係は[名前解決の仕様](current-specification.ja.md#ファイル名からアイコンを選ぶ規則)に従う。Windows全体の文字比較規則を完全再現する保証はしない。

## アイコンパックと多言語

利用者がアイコンパックを選択・変更できることを要件とする。テーマ定義にあるファイル名、拡張子、素材の対応関係を再利用し、追加や変更を可能な限り設定・テーマ定義で完結させる。

特定の初期パックへ固定せず、vscode-icons、Material Icon Theme、Catppuccin Icons、Symbols、VSCode Great Iconsの確認済みの版を選択できる。すべてのVS Code拡張を無条件で互換とする保証はしない。

取り込み時に、ファイル名・拡張子・言語識別子の規則が未定義のアイコンを参照していれば、その規則だけを警告付きで除外する。除外内容を保存し、GUIとCLIから確認できるようにする。有効な規則の優先順位は維持し、すべての対応規則が除外されたテーマは取り込まない。定義済みの画像の欠落や安全性検査の失敗は、警告で継続せず取り込みを失敗させる。

利用者向けの操作案内、エラー、導入・削除手順は英語と日本語に対応させる。GUIの言語選択とCLIの言語指定で切り替える。内部識別子や設定の機械的な値は表示言語から独立させる。

## GUIとデザイン

画面内の移動では上部の戻る操作、Alt＋←、マウスの戻るボタンを提供し、対象編集の下書きを保持する。競合時の強調とスクロールバーを含む表示・操作の契約は[デザイン規約](ui-design.ja.md#画面の移動とスクロール)に従う。

GUIを初期版から必須とし、GPUI / GPUI Kitを用いる。アイコンパックの選択・適用・切替、適用状態の確認、元の表示への復元と削除の主要操作をGUIから実行できること。日常の主要操作にCLIの入力を必須にしない。補助CLIも提供し、GUIと同じ管理処理、排他、取得上限、復元規則を使う。[CLI仕様](cli.ja.md)にコマンド、日英表示、JSONと終了コード、変更予定の確認、中断を定める。

デザインの原則と例外は[デザイン規約](ui-design.ja.md)、判断と検証の手順は[製品固有スキル](../.agents/skills/project-ui-design/SKILL.md)に従う。

### 登録競合からの明示的な復旧

GUI・CLIの両方から全競合と影響範囲を確認し、「外部の変更を保持して解除」または「アイコンパックを再適用」を明示的に選べること。初期選択は外部変更を保持する解除とする。再適用では変更箇所の現在値を新しい解除先として退避し、未変更箇所の解除先を維持する。後で通常解除しても、本アプリ自身の適用値を戻してしまわないこと。

実行確認は設定・記録・全登録値・対象パックと版・保存済み選択・同梱DLLに結び付ける。確認後の変化では実行を拒否し、変更予定を再取得させる。書き込み前の退避、途中失敗時の記録保持と再起動後の再試行を必須とする。既定アプリ・起動設定・ファイル内容と `.lnk`・`.exe` の保護を維持する。未知形式や不正な記録を強制確認で迂回しない。GUIの下書き・キャンセル・日英・進捗・重複操作抑止はGPUIのtest-support、CLIは実プロセスと隔離レジストリで検証する。詳細契約は[登録競合の復旧](conflict-recovery.ja.md)を参照する。

## パック取得と操作（0.1.0に含む）

アプリ内でのパック取得を0.1.0の必須機能とする。GPUI / GPUI Kitのtest-supportを使って主要操作を検証する。

- パック一覧から、作者、版、出典、利用条件を確認して取得できる。公式配布元の確認済みの版を掲載し、任意URLは受け付けない。
- 取得と適用を分ける。取得完了や更新の取得だけでExplorerの表示を変えず、利用者が「適用する」を選んで切り替える。
- 通信・検証と展開・ICO変換の進捗、キャンセル要求と完了、失敗の詳細、再試行を表示する。同時取得は一件に限る。
- ICO変換は、使用する画像定義の完了件数と総数、処理全体の経過時間を表示する。複数テーマは現在のテーマ番号とテーマ数を示し、画像件数をテーマごとに数える。残り時間は推定しない。
- 同じ提供元・拡張・テーマの別バージョンがあれば、設定引き継ぎの入口を取得済みパックへ表示する。一致する対象の保存済み設定だけを下書きへコピーし、追加・削除された対象を確認できる。旧版、旧版の設定、適用状態を保持し、明示的な保存・適用を必要とする。
- 取得後のプレビューには、Cargo.toml / settings.toml、package.json / data.json、README.md / notes.mdの実際の解決結果を表示する。入力したファイル名も確認でき、未対応ならWindowsの通常表示へ戻ることを示す。パックに専用アイコンがなければ、異なるものとして表示しない。
- パックの見本は保存済みの対象選択を反映し、保護判定を含めないことを明示する。各見本からファイル名を保持して対象編集の比較へ移動し、保護と下書きを含む保存後の表示予定を確認できる。移動だけで保存・適用はしない。
- パックの出典と権利表示を、素材と同じ期間保持する。一般のアイコンとブランドのアイコンで条件が異なる場合も、本体のMITと区別する。
- 取得済みパックと取得候補は明示的に切り替える。取り込み候補はキャンセルできる。パック削除は名前と削除範囲を示して確認し、キャンセルでは設定と素材を保持する。
- 適用中のパックを明示し、Windows標準へ戻す操作を常設する。適用中のパックは削除しない。削除要求を先に保存し、使用中のファイルや未知のファイルが残った場合は安全に再試行できる。
- 上部は言語・外観、適用状態・復元、一覧切り替え・取り込みの順に配置する。操作ボタンは通常時にも枠や背景を持たせ、押せる範囲を示す。選択中の状態とキーボードのフォーカスも区別する。
- 不正な配布物による資源消費や管理領域外への書き込みを防ぐ。通信・展開・変換には上限と時間制限を設ける。具体的な契約は[パック取得の設計](pack-downloads.ja.md)に記録する。

## 適用対象の選択

カテゴリ、拡張子、固有名、取り込み済みのパターンごとにアイコンの適用可否をGUIとCLIの双方で設定できること。カテゴリはパックに依存しない用途別の共通分類とし、固有名と同梱言語定義を使って分類を補い、用途が不明・競合する対象は未分類へ残す。分類表の更新後も対象識別子と保存済みの適用可否を保持する。検索結果と複数選択の一括変更、個別例外の解除、取り消し、結果の比較を備える。無効化した対象はWindowsの元の表示へ戻し、固有名の無効化後に拡張子のテーマ画像を返さない。保存・適用は明示操作とし、失敗時は下書きを保持する。具体的な契約は[適用対象の選択](target-selection.ja.md)に定める。

## 品質と導入・削除

- Explorerの操作を著しく遅くしない。表示要求時の処理を最小化し、SVG等の変換は原則として導入時に済ませる。表示ごとの外部プロセス起動を避ける。
- 解決失敗時は安全に通常表示へ戻す。Shell拡張によるExplorerのクラッシュ防止、既存ハンドラーとの競合、キャッシュと更新通知を検証する。
- 少ない操作で導入、パック切替、削除できるようにする。既存設定をバックアップし、削除時に元の表示へ復元する。既定アプリの関連付けを壊さない。
- 外部パックの出典、版、ライセンス、必要な表示を保持する。本体のMIT採用だけを理由に素材を再配布しない。

通常CIは既存のモック・契約試験とGPUI操作試験を使う。公開前とShellの登録・保護・委譲・復元やWindows API依存に影響する変更時には、対応対象のWindows 11 x64で実Shellの隔離試験を行う。公開候補の同梱DLLと実Explorerの受け入れを確認し、CIで未実施の試験を合格扱いにしない。コマンドと記録方法は[開発と検証](development.ja.md#windows-11での実shell検証)に定める。

性能の開発時の暫定予算と測定条件は[性能検証](performance.ja.md)、復旧処理の検証状況は[開発と検証](development.ja.md)に記録する。実Explorerでの性能と復元の受け入れは別に行う。

公開候補ごとに、次の基準を実Explorer・隔離試験・GUI操作試験へ対応させて確認する。各結果にはWindows版、対象コミット、成果物のSHA-256、パックと版、実行条件、未確認事項を記録する。以下は基準の一覧であり、チェック済みの合格証跡ではない。過去の版の結果を新しい公開コミットの検証結果へ読み替えない。

- Rust製Shell拡張がWindows 11の標準エクスプローラーで動作する。
- .json、.md、.rs等でテーマのアイコンを表示する。
- Cargo.tomlと通常の.tomlで異なるアイコンを表示する。
- package.jsonと通常の.jsonで異なるアイコンを表示する。
- README.mdと通常の.mdで異なるアイコンを表示する。
- 詳細表示と大アイコン表示の両方で正常に表示し、小・中・特大でも確認する。
- 新規作成と名前変更後の規則適用を確認する。
- 複数ディレクトリで個別設定なしに動作する。
- 既定アプリと対象ファイルの内容が変わらない。
- 未対応ファイルがWindowsの通常のアイコンを維持する。
- 削除後に元の表示と設定へ戻る。
- パックを選択・切替でき、切替前の素材や設定への参照が適切に更新される。
- 英語・日本語で主要な導入、選択、エラー、削除の案内を確認する。
- GPUI / GPUI Kit製GUIからパックの選択・適用・切替、状態確認、復元と削除を行える。
- GUIの主要操作とエラー表示を英語・日本語の双方で確認する。
- 確認済みの公式配布物をGUIから取得し、適用前のプレビューと出典・利用条件を確認できる。
- 取得を中断・再試行でき、失敗や取得完了だけで適用状態が変わらない。
- 通信量、展開量、項目数、時間の上限と、不正なパス・リンク・改変の拒否を確認する。
- GPUIのtest-supportで取得・中断・再試行・プレビュー・言語切替・操作制限を検証する。
- 既存ハンドラー競合、変換失敗、設定破損時に安全に扱える。

## 対応範囲と配布方針

Windows 11 x64、ユーザー単位の導入、展開済みVS Code拡張の取り込み、GUIと補助CLIを採用する。Windows 10、ARM64、システム全体の導入、フォント型テーマ、任意の祖先階層を必要とするパターンは対応範囲に含めない。

画像・動画のサムネイル提供元は変更しない。既存ハンドラーとの委譲は対応するインターフェースに限られ、すべての第三者拡張との互換性やExplorer全体の性能は保証しない。正式名、配布先、権利表示と成果物の対応は[配布手順](distribution.ja.md)で確認する。機能の完成と公開の承認は分ける。

## Windows固有アイコンの保護

「適用対象を選ぶ」で対象の選択と保護を含めた表示予定を同時に確認できること。保護中の対象も一覧と検索に残し、行から拡張子ごとの全パック共通の保護を明示保存できること。同じ関連付けクラスを共有する場合も拡張子ごとに保護・許可を独立して指定し、ほかの種類の方針を変更しない。カテゴリや状態によって検索結果が空の場合は、入力を保った全対象検索を提供し、パック自体の未対応と区別する。詳細は[適用対象の選択](target-selection.ja.md#gui)に従う。

`.lnk` と `.exe` は常にテーマ適用から除外し、Windows・アプリ・利用者が指定したアイコンを維持する。テーマの完全一致名やパターン、対象選択からこの保護を解除できない。GUI・CLI・Shell・登録計画で同じ方針を使い、旧登録は明示的な再適用時に復元記録から戻す。詳細は[適用対象の選択](target-selection.ja.md#windowsが管理するアイコンの保護)に従う。

「既定では既存アイコンを保護する」を全パックに共通の設定として提供し、既定で有効にする。拡張子または有効な関連付けクラスに空でない画像指定・専用アイコン処理がある場合、明示した例外がなければその種類の元アイコンを維持する。共有クラスに一部だけ許可した種類がある場合は、Shell拡張でファイル名を判定し、保護する種類を元の処理・画像へ委譲する。すべて保護するクラスへは登録しない。Windows標準の登録も対象とし、設定者や画像の見た目から独自設定かどうかを推測しない。

GUIから適用時に除外した種類・理由と、次回適用時の見込みを確認できること。設定の保存は明示操作とし、適用中なら退避済みの元登録へ戻してから再適用する。適用前の情報で判定し、本アプリ自身の登録を保護対象と誤認しない。外部変更による競合は自動で上書きしない。旧設定は既定有効として読み込み、読み込みだけでは登録を変更しない。設定を無効にしても `.lnk`・`.exe` の常時保護を維持する。詳しい判定と操作は[既存アイコンの保護設定](target-selection.ja.md#既存アイコンの保護設定)に従う。

ソフトに対応するアイコン提供元の一括指定と、拡張子ごとの例外をGUIで編集できること。ソフトの基本設定は「元のアイコン」「パックのアイコン」「全体設定に従う」、種類の個別設定は「元のアイコン」「パックのアイコン」「基本設定に従う」の三択で操作する。個別指定があっても親の基本設定の選択を維持し、個別設定の件数を表示する。基本設定の三択では個別指定を保持する。親子をまとめて戻す操作は「このソフトの設定を初期化…」へ分離し、警告で対象名と解除件数を示す。キャンセルでは下書きを変えず、確定後は親を全体設定、子を基本設定の継承へ戻す。提供元の表示は取得した資源情報に基づき、推定の根拠を保持し、不明な提供元を既定アプリ名から断定しない。ソフトごとの一覧をマウスとキーボードで開閉でき、取得できたソフトアイコンを名前に添えること。ソフトごとのカードと面の階層を使い、画像欄の最小幅を統一し、画像付きトグルから種類ごとの設定を選択できる。選択中のタイルだけを枠・チェック・画像の通常明度で強調し、継承タイルにはその設定を選んだ場合の実効画像を表示する。状態や代替表示の説明はツールチップで提供する。保護切替では再調査せず取得済み情報から表示を更新する。既存画像とパック画像の見本を表示し、適用中も退避済みの元指定を使う。同じ関連付けクラスでも保護設定と表示結果を拡張子ごとに分離する。提供元・登録・資源が変わった上書き許可は再確認する。抽出処理は別プロセスと期限・入力上限を使い、外部の専用ハンドラーを起動しない。詳細は[既存アイコンの保護設定](target-selection.ja.md#既存アイコンの保護設定)に従う。

Windowsパッケージアプリの間接資源参照を解決し、表示名とアプリアイコンを示す。同じアプリIDの素材は一つのカードへまとめ、パッケージ内の別アプリを混同しない。参照を解決できない場合も、素材名をソフト名として断定しない。

## 開発者向けのおすすめ保護設定

保護画面の「おすすめ設定」一回で、全体の既存アイコン保護を有効にし、VS Code由来のアイコンと代表的な開発用拡張子をパック優先へ設定できること。対象の個別保護も置き換え、反映後に手動調整して明示保存できること。詳細は[保護設定](target-selection.ja.md#開発者向けのおすすめ設定)に従う。

保護画面で、おすすめ操作直後の変更と保存済み設定からの下書きの変更を切り替えて確認できること。変更前後の保護方針と指定だけの変更を区別し、一覧から編集に戻れること。確認だけで保存・適用しない。
