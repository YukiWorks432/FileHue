# 性能とメモリーの検証

## 内容のサムネイル

`cargo build -p file-icons-thumbnail-shell --release --lib --example provider_probe --locked` で最適化したDLLと計測プログラムを用意し、`just perf-thumbnails work/performance/thumbnails.json <ファイル>...` を実行する。出力先のフォルダーは事前に作り、JSONは未作成の名前を指定する。CPUの排他手順がある環境では計測時に使用する。指定したファイルだけを読み、登録は変更しない。クラウド上の未取得ファイルを指定すると取得が発生し得るため、必要に応じて事前に状態を確認する。

各ファイルを新しいプロセスで2回取得し、形式と取得結果別の時間の中央値・95パーセンタイル、試験プロセス全体の最大ワーキングセット、個別の結果を記録する。OSのキャッシュを消さず、ファイルごとの処理時間であってExplorerの一覧表示時間ではない。フォントの初期準備、PDFや画像処理に伴うプロセス内の使用量を含むが、Windows全体の使用量や並列時のピークを示さない。対象数が少ない場合、95パーセンタイルは長期分布の推定にならない。JSONには入力の絶対パスが含まれるため、共有前に確認する。

## GUIと登録調査の比較

`just perf-gui work/performance/before-gui.json` と `just perf-icons work/performance/before-icons.json` で最適化構成の手動計測を実行する。ほかの負荷の高い試験と重ねず、共通のCPU排他がある環境ではその手順に従う。出力先は未作成のJSONとし、変更後は別名へ記録する。計測前にコミットし、作業ツリーに差分がないことを確認する。

GUIの計測は親プロセスが専用プロファイルを作り、子のWindows関連付けも専用キーへ隔離する。6,000対象の一覧描画・検索、400種類の登録調査と保護一覧・全開閉、32回の編集による取り消し履歴の保持量を測る。GPUIのtest-supportによるCPU側の要素構築・配置を含むが、GPUへの描画提示や実ウィンドウの起動時間を含まない。実DirectX描画の画像確認は別に行う。ICOは通常の7サイズと、32フレームの大きい入力を分ける。

各処理を3回ならした後に17回測り、生の時間、中央値・95パーセンタイル、Rustの割り当て回数と総バイト数、計測区間の最大生存量の増分と保持量を記録する。専用試験のアロケーター計数自体にも費用があるため、同じ計測構成の変更前後だけを比較する。これらの値はGPU資源、Windowsの内部確保、プロセス全体のメモリー上限を表さない。GUIの報告には専用コミット量とワーキングセットも別に記録する。

同じ入力・出力サイズ・表示条件・反復数で比較し、各条件の出力値も一致することを確認する。ICOの出力値は生成物のSHA-256の先頭64ビットであり、配布用の完全な照合情報の代わりにはしない。ソースのコミット、実行ファイルのSHA-256、CPU・OSと同時実行条件を報告へ添える。時間だけが改善してピークや保持量が増えた場合も併記する。報告と生ログは管理対象外の `work/performance/` へ置き、通常試験に時間の合否しきい値を追加しない。

描画には検索・変更件数の算出、カテゴリ欄、操作帯、行構築の内訳も記録する。`sections`の各値は順に包含時間のナノ秒、累積割り当てバイト数、呼び出し回数である。親区間と子区間は重なるため加算しない。検索の試験は文字列の入力、全選択、消去と複数回の描画を含み、一文字の応答時間ではない。GPUIの試験支援機能と配置処理にかかった残りの時間を、アプリの検索計算だけの費用として扱わない。

400種類の見本生成と、登録調査の結果をGUIへ反映する処理も独立して計測する。見本生成は実際の期限付き子プロセスを含むが、一つの資源を共有する合成データであり、128種類すべてが異なる資源の最大負荷を表さない。GUIへの反映には試験入力の複製を含む。結果表示と見本の後着を分けた場合は、操作可能になるまでの時間と全画像がそろうまでの時間を区別する。

追加条件として、400種類が別々の関連付けクラスを持つ登録計画、4クラス内で保護と許可が混在する計画、さらに400種類のパック外の共有先を含む計画を測る。拡張子側の静的画像と専用ハンドラーも含め、通常の利用者登録へ書き込まない。各条件のクラス数・保護件数・パック外の種類数を記録し、登録値・元の表示・委譲先・除外・作成キーの照合値を変更前後で比較する。400別クラスの条件だけは既存保護を無効にし、全クラスへの計画作成を測る。

8パック・各6,000対象と6,000件の個別指定を使い、一覧全体の設定読み込み、パック見本の描画、7候補の設定コピー画面、コピーの確定と取り消しを分けて測る。描画から確定操作へ処理を移す場合も、確定と取り消しを含む区間を比較する。各回の最大生存量と累積割り当てを区別する。

複数パックを保存した後の最初のウィンドウ構築から最初のCPU描画までの時間と、前後のプロセスメモリーも一回記録する。これは同じ試験プロセス内の観測であり、プロセス起動・OSのディスクキャッシュ消去・GPU提示を含まない。反復する設定読み込みの分布と区別し、実アプリの起動時間の保証に使わない。

同じテーマの8バージョンを使い、コピー画面の一致・追加・削除件数、選択コピー単体、カテゴリ選択中の描画とカテゴリ全体の変更・取り消しも測る。検索は日本語・英語のカテゴリ名、先頭のドットを含む拡張子の契約を操作試験で別に確認する。

`just perf-gui`は実CLIもビルドし、対象の一括編集・コピーの変更予定を別プロセスで測る。起動計測は空の一覧と8パックの一覧それぞれで、専用プロファイルを使う実DirectXウィンドウを作る。子の試験開始から設定読み込み・ウィンドウ生成の完了、最初の描画命令までを記録し、その時点のプロセスメモリーを取得する。親の時間はプロセス生成から終了までを含み、最初の画面が表示された時刻ではない。OSのディスクキャッシュは制御せず、GPUによる画面提示の完了も保証しない。子の確保量は親のRustアロケーターでは測れないため、CLI・起動の割り当て値を比較に使わない。

個別の再測定には`WFI_PERF_FOCUS=1`で登録計画・登録報告・元画像生成の反復を除ける。記録した条件が異なる報告を直接比較しない。起動の非同期化は設定読み込みと画面生成の実測から判断し、最初の表示と操作可能になるまでの時間、追加状態と失敗時の復旧の負担も評価する。

## Shellアイコン取得

測定対象は最適化ビルドの実DLLである。`DllGetClassObject` からCOMオブジェクトを生成し、`IPersistFile::Load` と `IExtractIconW::GetIconLocation` を呼び出す。既存のWindows登録は変更しない。Windowsの標準エクスプローラーの操作全体を測った結果とは区別する。

## 測定範囲

親プロセスが、実パックを読み取り専用で取り込み、専用の一時プロファイルを作る。実際の登録計画を読み取りで作成し、同量の変更前後の値と独立した復元記録を含めるが、計画は実行しない。測定対象のDLLを読み取りで開いて、全測定の間は書き込みと削除を共有しない。同じバイト列を読み込んだことをSHA-256で記録する。

各条件について新しい子プロセスを8回起動する。子の `LOCALAPPDATA` だけを変更し、実ユーザーの設定を使わない。以下を分けて記録する。

- DLLの読み込みとクラスファクトリーの取得。
- そのプロセスで初めて行うアイコン位置の取得。設定と復元記録の読み込み・解析を含む。
- 設定を再利用できる場合の位置取得256回。毎回COMオブジェクトを生成し、名前解決とCOMの呼び出しを含める。
- `ExtractIconExW` による大小のアイコンの取り出しと `DestroyIcon` による解放。
- 専用設定の原子的な置き換え後、最初の位置取得。設定の書き込み自体は測定へ含めない。
- 設定読み込み前と反復取得後のワーキングセット・プライベートメモリー。
- 同じファイルに対する関連付け照会の単独実行と、委譲先のWindows標準COMの直接実行。これらは本体の位置取得の計時外で交互に行う。

各呼び出しで、選んだ素材とアイコン番号が期待結果と一致することも確認する。素材と番号の一致は時間の外で照合する。成功判定とバッファ・フラグの妥当性確認は測定処理に含む。取り出した大小のアイコンは反復ごとに解放する。[ExtractIconExWの戻り値](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-extracticonexw)は成功した取り出しの個数である。Windows標準DLLは、大小両方の取得に対して取得個数2を返す場合があるため、取得個数だけを1へ固定せず、有効な両ハンドルも照合する。

条件は、特定ファイル名、拡張子、未対応名の静的な通常表示、ShellLinkによるファイルごとのアイコンの委譲である。委譲では本物のWindows標準COMを使用する。Visual Studioなどの第三者ハンドラーの性能・互換性は、この試験の対象に含めない。

## 実行

MSVCのWindows環境で次を順番に実行する。測定はほかの負荷の高い試験と重ねず、共通のCPU排他がある環境ではそれを使う。ビルド単独は排他対象としない。ビルドや素材変換は、アイコン要求の測定区間へ含めない。

```powershell
cargo build -p file-icons-shell --release --locked
cargo build -p file-icons-shell --example measure_shell --release --locked
./target/release/examples/measure_shell.exe ./target/release/file_icons_shell.dll work/performance/report.json <展開済み拡張フォルダー>...
```

先頭の拡張フォルダーの最初のテーマを適用中とする。`package.json` と `.json` の規則を持つテーマが必要である。他の入力テーマも設定へ保存し、複数パックを取得した状態の読み込み量へ反映する。生の試行値、版、規則数、設定のサイズ、DLLのSHA-256をJSONへ出力する。既存の報告は上書きしない。

プロセスごとの初回を測るが、OSのファイルキャッシュは空にしない。DLL、設定、画像がディスクキャッシュにない場合の時間を保証しない。ウイルス対策や他のアプリによる変動も含みうる。初回の95パーセンタイルは8試行の最大値になるため、長期の分布の推定には使わない。設定再利用時は各条件2,048回の値を集計する。

## 判断の扱い

アイコン位置取得の追加処理は、1,000ファイルでの処理量を抑えるため、設定再利用時の中央値0.2ms以下、95パーセンタイル1ms以下を開発時の暫定目安とする。初回と設定の再読み込みには中央値50ms以下、各試行100ms以下を目安とする。これらは本体のCOM経路の予算であり、Explorerの一覧表示時間を保証しない。Windowsによる画像取り出しは別に記録する。委譲先そのものが必要とする時間は単独の比較値を併記し、本体の追加処理と区別する。分布の中央値の差だけから、差分の95パーセンタイルを保証しない。

実Explorerでは、アイコン表示の各モード、新規作成・名前変更、サムネイル、既定アプリの保持、復元、操作の停止や著しい遅延がないことを改めて確認する。上記の数値を満たしても、その受け入れを完了扱いにしない。


## 結果の保存と比較

過去の開発時の測定値は公開版の性能保証へ引き継がない。報告書は `work/performance/` など管理対象外の場所へ保存し、比較するソース・DLLのSHA-256、パックの版、OS・CPU・表示条件、反復数、中央値・95パーセンタイルを併記する。公開する結果は個人パスと元データの権利も確認する。

長時間待機は本体のCOM処理、関連付け照会、委譲先、画像抽出を分けて診断する。STAとMTAも別条件で記録する。測定用プロセスは期限とログを持たせ、待機を延ばしただけで正常と扱わない。制御の範囲は[開発と検証](development.ja.md#試験プロセスの待機期限と診断)を参照する。
