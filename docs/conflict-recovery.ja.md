# 登録の競合を確認して復旧する

外部アプリがアイコン関連の登録を変更すると、通常の適用・復元は競合として停止します。アプリが保存している値と現在値が異なるためで、再起動やビルド成果物の削除では解消しません。「競合を確認…」から対象と処理後の見込みを調べ、明示的に復旧方法を選びます。

Windowsが現在の関連付けとして `Applications\Illustrator.exe` のようなアプリ登録先を返す場合も、外部変更を保持する解除の計画を確認できます。関連拡張子の表示に使う照会結果を、新しい書き込み先としては使いません。解除は保存済みの登録先と現在値を照合して行い、既定アプリやアプリの起動設定を保持します。再適用で書き込み先として扱えない関連付けに遭遇した場合は、その拡張子と照会結果を示して停止します。

## 復旧方法と解除先

| 方法 | 処理 | 完了後 |
| --- | --- | --- |
| 外部の変更を保持して解除 | 本アプリの適用値を元へ戻し、外部変更と解除済みの値を保持する | パック適用なし |
| アイコンパックを再適用 | 確認した登録を上書きし、記録にあるパックと保存済みの対象選択を適用する | パック適用中 |

初期選択は外部変更を保持する方法です。再適用では、変更されていない箇所の元の解除先を維持し、外部変更があった箇所だけ現在値を新しい解除先にします。たとえば別アプリの画像設定を上書きしても、その後の通常解除では退避した別アプリの設定へ戻ります。本アプリ自身の適用値を新しい解除先として保存しません。

再適用するパック・版・保存済み選択を確認します。通常設定の適用状態が空でも、独立した復元記録が残る場合は、その登録を作ったパックを記録から識別します。通常表示の適用状態を自動的に書き換えず、再適用の明示確認に使います。パックの記録、素材の定義、同梱Shell DLLが使えなければ再適用を始めません。有効な規則の変換済みアイコンを計画時と書き込み前に開き、通常ファイルで空でないことを確認します。未保存の下書きは復旧画面への移動で保持し、自動的には適用しません。パックが利用できなくても、設定と復元記録が健全なら外部変更を保持する解除を選べます。

## GUIで確認する

上部の「競合を確認…」を開きます。競合エラーからも同じ入口を案内します。画面は外部変更のある箇所を先に表示し、全件表示へ切り替えられます。登録の種類、関連付けを共有する拡張子、現在値と処理後の見込みを確認します。画像の比較に必要な外部DLLやCOMを読み込まず、画像パス・番号などの文字情報を表示します。

キー、値名、型、記録にある適用値、新しい解除先などは「詳細」で確認します。1ページ50件、文字列の表示は1024 UTF-16単位を上限とし、長いパスは列幅で省略します。各行の「登録の詳細をコピー」で完全なJSONを取得でき、CLIでも型とバイト列を確認できます。退避先は詳細と最終確認に表示し、「パスをコピー」で完全な場所を取得します。

方法はラジオボタンで選びます。この選択だけでは設定を変更しません。利用できないパックや素材がある場合は再適用を無効にして理由を表示します。「変更内容を確認…」へ進み、対象件数、書き換え件数、パック・版・選択、退避先を確認してから最終ボタンを押します。「外部変更を保持して解除」または件数付きの「上書きして再適用」で確定します。Escapeは最終確認から一覧へ戻り、一覧では元の画面へ戻ります。実行前に戻る操作では設定と登録を変更しません。画面を開くとキーボードのフォーカスを移し、キャンセル時は元の入口へ戻します。TabとSpaceでも復旧方法を選べます。再適用の個別指定は詳細に最大50件を表示し、完全な選択内容もコピーできます。

処理中は実行操作の近くにスピナーを表示し、重複操作を抑止します。失敗した場合は理由を確認し、「再確認」で変更予定を取得し直します。完了後の表示が変わらなければ、ファイル操作を終えてからExplorerを再起動します。Explorerはアプリから自動終了しません。完了後は結果を専用表示に切り替え、実行ボタンを除いて再実行を防ぎます。既に復元済みの登録と変更が必要な登録の件数は区別します。書き換えが0件でも記録が残る場合は記録の整理を案内し、復旧対象の記録自体がなければ実行へ進めません。

## CLIで確認する

GUIを閉じ、同じ利用者のターミナルから実行します。

```powershell
.\file-icons.exe conflicts list --json
.\file-icons.exe recover --strategy preserve-external --dry-run --json
.\file-icons.exe recover --strategy reapply-theme --dry-run --json
```

`conflicts list` は外部変更を保持する解除の計画を直接返します。`recover --dry-run` は `data.plan` に計画を返します。計画の `confirmation` を複写し、同じ方法で実行します。以下の山括弧は説明用であり、そのまま入力しません。

```powershell
.\file-icons.exe recover --strategy preserve-external --confirm <confirmation> --json
.\file-icons.exe recover --strategy reapply-theme --confirm <confirmation> --json
```

確認用識別子は設定・ライブラリ・独立した復元記録・途中処理記録の生バイト、現在の登録、最終設定、パック・版・選択、同梱DLLの内容に結び付きます。状態や方法が異なれば実行を拒否し、計画の取り直しを求めます。入力待ちは行いません。`--confirm` のない実行、`--dry-run` と `--confirm` の併用、別コマンドでの方法指定、未知の方法は引数不正になります。

計画の主なフィールドは次のとおりです。

| フィールド | 内容 |
| --- | --- |
| `schema_version` | 計画形式1 |
| `confirmation` | 確認用の64桁の識別子 |
| `strategy` | `preserve-external` または `reapply-theme` |
| `pack_id` / `pack_label` / `pack_version` / `selection` | 再適用するパックと保存済み選択 |
| `conflicts` / `writes` / `overwrites` | 外部変更、書き換え、既存値への上書きの件数 |
| `backup` / `resuming` | 退避先と未完了処理からの再開かどうか |
| `entries` | キー・値名・関連拡張子・状態・値の一覧 |

各行の `state` は `external`、`applied`、`original`、`new` です。`current` は観測値、`recorded` は記録にある本アプリの適用値、`original` は今回採用する解除先、`planned` は処理後の値を表します。値なしは `null`、値ありは `kind` と `bytes` で表し、Windowsの値の型と生バイトを保持します。キーや状態識別子は翻訳しません。

関連付けクラスの綴りだけが変わった再適用でも、既存記録の同じ登録先と変更前の生値を引き継ぎます。自分が適用した値を解除先として再取得しません。通常適用・再適用とも、所有範囲と小文字化した登録先の一意性を保存・書き込み前に検証します。重複した解除先を含む計画や不正な記録は、読み飛ばして適用せず拒否します。

確認後の変化は `registration_conflict`、終了コード6になります。読み取れない記録、未完了の復旧などは `recovery_required`、終了コード7として報告します。引数不正は2、他の管理操作の使用中は3です。実行成功は `recovered: true` と実行した計画を返します。`status` の `conflict_recovery_pending` でも未完了処理を確認できます。

既存の `apply`・`restore`・方法指定なしの `recover` の競合時停止と呼び出し方は維持します。無条件に上書きする `--force` と確認を省く `--yes` は提供しません。

## 保存と再試行

設定・記録・計画は利用者データの `conflict-backups/<confirmation>/` へ退避します。退避内容と計画を同期保存してから、`conflict-operation.json` に元の設定、新しい解除先、処理予定を保存します。退避の失敗では登録を書き換えません。同じ計画の退避を再利用する場合も内容の一致と保存先の実体を確認します。退避は自動削除しません。Windowsの保存先仮想化では、通常のディレクトリでも要求したパスと実体のパスが異なる場合があります。退避領域と確認用識別子のディレクトリがリンク・再解析ポイントでないことを検査し、解決した実体の中へ保存します。既存領域のプレビューと実行結果には実体の退避先を表示します。初回作成時は実行時に実体が確定するため、その実体を退避した計画と結果へ記録します。

再適用するShell DLLも、通常ディレクトリの保存先仮想化とリンクを区別します。初回配置で実体の場所が確定した場合は、確認した配置先と同じファイルであることを照合し、Explorerが読み取れる実体のパスを登録予定・復元記録・退避した計画へ反映します。計画の取得だけではDLLを配置せず、確認したDLLの内容や登録対象を変更しません。

実行直前と各登録の書き込み前に観測値を照合します。新しい外部変更は上書きせず停止します。設定保存の直前も入力ファイルを照合し、実行開始後の編集を上書きしません。処理中の外部変更や入出力失敗は、完了した変更も含む予定と解除先を処理記録に残します。再起動後は状態を再確認し、新しい確認用識別子を取得して続けます。途中で既に書き換えた値を外部変更や元の解除先と誤認しません。

全登録値と最終設定の保存結果を確認し、通常の解除に使う独立した記録を整えてから途中処理記録を除去します。未完了の記録が残る間は通常の変更操作を止め、確認付きの復旧を使います。保存形式の非対応や破損は、確認操作でも読み飛ばしません。各入力・記録のJSONは16 MiBまでとし、上限超過では変更前に停止します。

上書きできるのは登録記録のアイコン値・ハンドラーと本アプリ固有のCOM登録だけです。既定アプリ、UserChoice、起動コマンド、ファイル内容は変更しません。再適用計画の追加対象も確認へ含めます。[保護対象](target-selection.ja.md#windowsが管理するアイコンの保護)の `.lnk`・`.exe` と同じ関連付けクラスは再登録せず、旧登録は解除側の計画で扱います。

GUI・CLIは同じ管理サービスとロックを使います。GPUI操作試験、実CLIの入出力、隔離レジストリでの外部変更・退避失敗・設定保存失敗・再開、書き込み途中の競合・失敗を検証します。実Explorerの画面受け入れはこれらの自動試験とは区別します。

## 破損設定の保存と退避の境界

通常保存はShell用設定とパック一覧の本文まで解析し、破損・非対応形式を上書きしません。両ファイルがない場合は新規作成します。設定が読めないときの解除は独立した復元記録を検証し、両原本の完全な退避を作成してから登録を変更します。退避は1ファイル16MiB以内とし、上限を1バイトでも超えた入力、読み取り途中の増大、退避失敗では登録を変更せず原本と復元記録を保持します。切り詰めたコピーを完成した退避として残しません。

通常保存の検査を省略できるのは、完全な退避を作成した明示復旧の内部経路だけです。保存直前に退避時の原本と照合し、変更されていれば置換せず再試行を案内します。上限を超える原本はこの復旧方法では解除できず、元ファイルを保持したまま別途の復旧判断を必要とします。
